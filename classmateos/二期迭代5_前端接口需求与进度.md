## 3. 权限点

`GET /users/me`（以及登录、刷新返回的 user）新增 **`permissions: string[]`**，是当前用户所有角色权限的并集。前端用它决定显示哪些后台页和操作。**没有这个字段时，`role == "admin"` 视为拥有全部权限**（兼容旧后端）。

| 权限点 | 前端用途 |
|---|---|
| `admin.members` | 成员管理页 |
| `admin.departments` | 组织架构页 |
| `admin.roles` | 角色与权限页 |
| `admin.audit` | 操作日志页 |
| `admin.security` | 安全设置页 |
| `table.create` / `table.delete` | 新建表（含从文件新建）/ 删除表 |
| `doc.delete`、`doc.share`、`doc.template` | 文档删除、分享、模板（显示用） |
| `wiki.create` | 新建知识空间 |
| `org.departments` | 作为权限点名称出现在角色勾选里 |

权限点显示名在前端 `kPermissionPoints` 里；后端如新增权限点，前端会直接显示键名，不会出错。**前端只做显隐，后端每个接口仍要校验并返回 403。**

内置角色用 `builtin` 标识：`super_admin`（全部权限，不可改、不可删、至少保留 1 人）、`admin`、`member`（可改权限，不可删）。

## 4. 接口清单

### 4.1 「我的」页

| 接口 | 请求 | 返回 / 说明 |
|---|---|---|
| `PATCH /users/me` | `{status_text?, phone?, avatar_file_key?}` | 更新后的 user。头像先走现有上传接口拿 `file_key` |
| `POST /users/me/password` | `{old_password, new_password}` | 204。旧密码错 → 400 `INVALID_PASSWORD`；不满足安全设置的密码规则 → 400 `WEAK_PASSWORD`（`message` 写清规则）。**改密后其他设备的令牌要失效，当前设备保留** |
| `GET /users/me/sessions` | — | `items: [{session_id, device_name, platform, ip, last_active_at, created_at, current}]`，`current: true` 标当前设备 |
| `DELETE /users/me/sessions/:session_id` | — | 204。被踢的设备下次请求返回 401 |
| `POST /users/me/logout-all` | — | 退出除当前设备外的所有设备 |

`user` 对象新增 `status_text`、`phone`、`permissions`（见第 3 节）。

### 4.2 成员管理（R-AD-01）

| 接口 | 请求 | 返回 / 说明 |
|---|---|---|
| `GET /users?include=admin` | `q, department_id, status(active/disabled), page_size, page_token` | 带管理字段的成员：`username, status, last_login_at, department_ids, primary_department_id, leader_id, role_ids` 以及原有 user 字段。不带 `include=admin` 时按原来的通讯录格式返回，普通成员可调 |
| `POST /users` | `{username, name, email?, phone?, title?, department_ids?, primary_department_id?, leader_id?, role_ids?}` | 新成员 + 一次性 `initial_password`（前端只展示一次）。用户名重复 → 409 `USERNAME_EXISTS` |
| `PATCH /users/:user_id` | 同上字段任意组合；`{status: "active" | "disabled"}` 用于停用 / 启用 | 更新后的成员。停用后该账号所有令牌立即失效，登录返回 403 |
| `POST /users/:user_id/reset-password` | — | `{password}` 一次性新密码 |
| `POST /users/:user_id/logout-all` | — | 强制下线该成员所有设备 |
| `GET /users/import/template` | — | `{file_key}`，前端用现有下载接口下载 xlsx 模板 |
| `POST /users/import/preview` | `{file_key}` | `{headers, rows: string[][], total_rows, errors: [{row, message}]}`，`row` 为数据行下标（从 0 起，对应 `rows`） |
| `POST /users/import` | `{file_key}` | `{job_id}`，进度见 4.8 |

不能停用自己；不能停用最后一名超级管理员（返回 400，`message` 说明原因）。

### 4.3 组织架构（R-AD-02）

| 接口 | 请求 | 返回 / 说明 |
|---|---|---|
| `GET /departments` | `parent_id`（`root` 表示最上层）、`page_size` | `items: [{department_id, name, parent_id, leader_id, member_count, has_children, order}]`。普通成员可调（通讯录浏览） |
| `GET /departments/:id` | — | 单个部门；不存在 404 |
| `GET /departments/:id/path` | — | `items`：从根到本部门的部门数组，名片拼「A / B / C」 |
| `POST /departments` | `{name, parent_id(null 为最上层), leader_id?}` | 新部门 |
| `PATCH /departments/:id` | `{name?, leader_id?(null 清空), parent_id?, order?}` | 拖动移动时同时发 `parent_id` + `order`。不能移到自己的子部门下（400） |
| `DELETE /departments/:id` | — | 有下级部门或成员时 409，`message` 写原因 |
| `POST /departments/:id/members` | `{user_ids}` | 加入部门 |
| `DELETE /departments/:id/members/:user_id` | — | 移出部门 |
| `GET /users?department_id=` | — | 部门直属成员，普通成员可调 |

`member_count` 建议含下级部门成员（前端显示「N 人」）；只算直属也可以，请在对接说明里注明。

### 4.4 角色（R-AD-03）

| 接口 | 请求 | 返回 |
|---|---|---|
| `GET /roles` | — | `items: [{role_id, name, description, builtin, permissions, member_ids}]` |
| `POST /roles` | `{name, description?, permissions}` | 新角色。重名 409 |
| `PATCH /roles/:role_id` | `{name?, description?, permissions?}` | 更新后的角色。`super_admin` 改权限 → 400 |
| `DELETE /roles/:role_id` | — | 内置角色 400 |
| `PUT /roles/:role_id/members` | `{user_ids}`（**整体覆盖**） | 更新后的角色。`super_admin` 清空成员 → 400 |

改了角色或成员后，受影响用户的 `permissions` 下次 `GET /users/me` 要是新的。前端在自己改角色后会主动刷新一次。

### 4.5 操作日志（R-AD-04）

| 接口 | 请求 | 返回 |
|---|---|---|
| `GET /audit-logs` | `start_at, end_at`（ISO UTC），`operator_id, action, page_size=50, page_token` | `items: [{log_id, created_at, operator_id, operator_name, action, target_type, target_id, target_name, detail, ip, device}]`，按时间倒序 |
| `POST /audit-logs/exports` | `{format: "csv", start_at?, end_at?, operator_id?, action?}` | `{job_id}`，完成后 `result.file_key` |

前端对以下 `action` 做了中文名和颜色（其他值原样显示）：`auth.login`、`auth.login_failed`、`auth.logout`、`user.create`、`user.update`、`user.disable`、`user.enable`、`user.import`、`user.reset_password`、`user.logout_all`、`role.change`、`department.change`、`security.update`、`doc.delete`、`table.delete`、`record.delete`。建议后端统一用这些值。

### 4.6 安全设置（R-AD-05）

`GET /admin/security-settings`、`PUT /admin/security-settings`，请求与返回同结构：

```json
{
  "password_min_length": 8,
  "password_require_letter_digit": true,
  "force_change_on_first_login": true,
  "access_token_ttl_minutes": 120,
  "idle_timeout_minutes": 0,
  "lock_after_failures": 5,
  "lock_minutes": 15
}
```

`idle_timeout_minutes: 0` 表示不启用。校验失败返回 422 + 中文 `message`。
**已确认并实现**：登录 / 刷新返回顶层和 user 里带 `must_change_password: true`，前端进入强制改密页；其他接口返回 403 `PASSWORD_CHANGE_REQUIRED` 时也会进入。

### 4.7 扫码登录（R-LG-02）

| 接口 | 鉴权 | 请求 | 返回 |
|---|---|---|---|
| `POST /auth/qr` | 无 | `{device_name}` | `{qr_id, qr_content, expires_at}`，有效期 2 分钟 |
| `GET /auth/qr/:qr_id` | 无 | — | `{status, scanned_by_name?, device_name?, session?}` |
| `POST /auth/qr/:qr_id/scan` | 需要 | — | 同上（返回 `device_name` 给手机显示「要登录 XXX」） |
| `POST /auth/qr/:qr_id/confirm` | 需要 | — | 204 |
| `POST /auth/qr/:qr_id/cancel` | 需要 | — | 204 |

- `status`：`waiting` → `scanned` → `confirmed`，或 `expired` / `canceled`。
- `qr_content` 格式固定为 **`classmateos://qr-login?qr_id=<id>`**，前端据此识别。
- `confirmed` 时 `session` 与登录接口返回完全一致（`access_token`、`refresh_token`、`expires_in`、`user`），**只返回一次**，之后再查该 `qr_id` 返回 404 或 `expired`。
- 桌面端每 2 秒轮询；查询返回 404 当作过期。
- 建议对 `POST /auth/qr` 和轮询做频率限制（无鉴权接口）。

### 4.8 异步任务（导入导出共用）

`GET /jobs/:job_id`：

```json
{
  "job_id": "job_1",
  "status": "pending | running | done | failed",
  "progress": 0.6,
  "message": "第 12 行：数量必须是数字",
  "result": {"file_key": "...", "file_name": "项目.xlsx", "succeeded": 98, "failed": 2, "error_file_key": "..."}
}
```

- 导出完成时 `result.file_key` + `file_name`，前端自动下载；**请在下载接口的 `Content-Disposition` 里带上这个文件名**。
- 导入完成时 `succeeded` / `failed`，有失败时 `error_file_key` 是失败明细文件（前端提供下载）。
- 前端优先听 WS 事件 **`job.updated`**（载荷与上面相同），同时每 2 秒轮询兜底；只能查自己发起的任务，别人的返回 404。

### 4.9 多维表格导入导出（R-BT-07）

| 接口 | 请求 | 返回 |
|---|---|---|
| `POST /tables/imports/preview` | `{file_key}`（xlsx / csv，前端限 20 MB） | `{headers, rows（前 20 行）, total_rows, suggested_types: {表头: 字段类型编号}}` |
| `POST /tables/:key/imports` | `{file_key, mode: "append" | "upsert", mapping: {列名: 字段名}}` | `{job_id}`。`upsert` 按主字段匹配，没匹配上的追加；不导入的列不放进 `mapping` |
| `POST /tables/:key/exports` | `{format: "xlsx" | "csv", view_id?, record_ids?}` | `{job_id}`。有 `view_id` 时按视图的筛选、排序、隐藏列导出；有 `record_ids` 时只导出这些 |

**用文件新建表**：前端先 `POST /tables/imports/preview`，用户确认字段名和类型后调用已有的 `POST /tables` 建表，再调 `POST /tables/:key/imports`（`mode: append`）。后端不需要单独的「从文件建表」接口。
CSV 编码请同时支持 UTF-8（含 BOM）和 GBK（Windows Excel 导出的 CSV 常见）。单元格格式不对的行计入 `failed`，不要整批失败。

### 4.10 文档导出（R-DC-06）

`POST /docs/:doc_id/exports {format: "pdf" | "docx"}` → `{job_id}`，进度见 4.8。图片需一起导出。前端在文档有未保存修改时会先拦下，提示保存后再导出。Markdown 由前端直接生成，不调接口。

### 4.11 工作台（R-WB-01、R-WB-02）

| 接口 | 请求 | 返回 |
|---|---|---|
| `GET /workbench/apps` | — | `{builtin: ["messages","bitable","wiki",...] 或 [{key}], shortcuts: [...]}`。`builtin` 决定内置应用的顺序和是否显示，值与前端模块名一致：`messages, calendar, bitable, docs, wiki, tasks, drive, contacts` |
| `PUT /workbench/shortcuts` | `{shortcuts: [...]}`（**整体覆盖**，顺序即显示顺序） | `{shortcuts}`，新项由后端分配 `id` |
| `GET /dashboard/summary` | `range: week | month | semester | custom`，`custom` 时带 `start_at`、`end_at`（ISO UTC，`end_at` 为开区间：次日 0 点） | 与一期报表六卡格式相同 |

快捷方式对象：`{id, type: "table_view" | "wiki_space" | "doc", target_id, name, icon?, table_key?}`。`table_view` 时 `target_id` 是视图 ID，`table_key` 是表。快捷方式是**个人**的；目标被删或没权限时请照常返回，前端点开后会提示「无法打开」。
**待后端确认**：「本学期」的起止日期由后端决定（建议在安全设置旁提供配置），前端只传 `semester`。

### 4.12 Web 版与分享链接（R-LG-01）

前端路由（Web 地址栏 / 分享链接）：

| 页面 | 路径 |
|---|---|
| 会话 | `/messages/:chat_id` |
| 文档 | `/docs/:doc_id` |
| 任务 | `/tasks/:task_id` |
| 知识空间 / 页面 | `/wiki/spaces/:space_id`、`/wiki/:node_id` |

**需要后端（或部署）配合**：Web 静态站点对以上路径都返回 `index.html`（SPA 回退），否则刷新会 404。分享链接的域名取 `capabilities.web_url`。

## 5. 实时事件

| 事件 | 前端处理 |
|---|---|
| `job.updated` | 更新任务进度弹窗（见 4.8） |
| `user.updated` | 重新拉成员列表（姓名、部门、头像等） |
| `department.changed` | 重新拉成员列表 |
| `permissions.changed` | **前端新增的约定**：自己的角色或权限点变化时推给本人，前端重新调 `GET /users/me` 刷新 `permissions` |
| `capabilities.changed` | 重新取开关（迭代 1 已有） |

被强制下线、停用、或改密导致令牌失效时，接口返回 401 且刷新令牌失败，前端回到登录页并提示「登录已过期，请重新登录」。不需要额外的 WS 事件。

## 6. 错误码（前端有专门处理的）

| code | 场景 | 前端表现 |
|---|---|---|
| `INVALID_PASSWORD` | 改密时旧密码错 | 提示写在「当前密码」输入框下 |
| `WEAK_PASSWORD` | 新密码不满足规则 | 提示写在「新密码」输入框下，直接用 `message` |
| `USERNAME_EXISTS` | 新建成员用户名重复 | 提示写在用户名输入框下 |
| 其他 4xx | — | 弹出 `message` |
