## 1. 标记与优先级

| 标记 | 含义 |
|---|---|
| 【已有】 | 后端已实现，前端正在用，**保持兼容即可** |
| 【需修改】 | 接口已存在，但行为或返回字段不满足前端需要 |
| 【新增】 | 后端目前没有，需要新增 |

| 优先级 | 含义 |
|---|---|
| **P0** | 正确性 / 安全问题，现在前端功能有缺陷或有越权风险，必须先做 |
| **P1** | 对标飞书核心体验需要，做完前端才能去掉临时做法 |
| **P2** | 增强项，可排在后面 |

**兼容原则**：所有改动只做「加字段、加参数、加接口」，不删除、不改名已有字段。前端解析时对缺失字段都有默认值，后端可以分批上线。

## 2. 通用约定

### 2.1 基础地址

- REST：`{origin}/api/v1`，前端默认 `http://localhost:8080/api/v1`，登录页「服务器设置」可改
- 用户 WebSocket：`ws(s)://{host}/api/v1/events/ws?token=<access_token>`
- 文档协同 WebSocket：`ws(s)://{host}/api/v1/docs/{doc_id}/collab?token=<access_token>`
- 签名直传 / 直取地址（`upload_url`、`download_url`）可以是绝对地址，也可以是以 `/` 开头的相对地址，前端会自动拼上 origin

### 2.2 请求

- 除文件直传外，请求体都是 `Content-Type: application/json`，UTF-8
- 鉴权：`Authorization: Bearer <access_token>`
- **GET 请求不带请求体**（浏览器和部分代理会拒绝），参数全部走 query
- 非 GET 请求即使没有参数，前端也会发送 `{}`，后端不要因此报错

### 2.3 返回

- 成功：`200 / 201` 返回 JSON 对象；`204` 无内容（前端按空对象处理）
- 列表统一结构：

```json
{
  "items": [],
  "has_more": false,
  "page_token": "下一页游标，没有下一页时省略",
  "total": 0
}
```

`total` 可选，有的话前端用来显示条数；没有时前端显示已加载条数。

### 2.4 错误格式

所有 4xx / 5xx 返回：

```json
{
  "message": "给人看的说明",
  "code": "可选的机器可读错误码，如 CHAT_NOT_MEMBER",
  "errors": [ { "field": "status", "message": "必须是以下之一：进行中、完成" } ]
}
```

前端对状态码的处理（`api_client.dart:21` `CosApiException.friendly`）：

| 状态码 | 前端显示 | 对后端的要求 |
|---|---|---|
| 0（网络失败） | 连不上服务器，请检查网络或服务地址 | — |
| 400 | 直接显示 `message` | `message` 请写**中文** |
| 401 | `message == "invalid credentials"` 时显示「用户名或密码错误」，否则显示「登录已过期，请重新登录」（目前只提示，不会自动跳回登录页；接入 4.2 后改为先自动刷新令牌） | 登录失败的 `message` 保持 `invalid credentials` 不变 |
| 403 | 没有权限执行这个操作 | — |
| 404 | 内容不存在或已被删除 | — |
| 409 | 直接显示 `message` | 新增的冲突场景（如卡片已回答）用 409 |
| 422 | 有 `errors` 时逐条显示「字段（原因）」 | **P1：`errors[].message` 改成中文**，目前是 `expected string` 这类英文，会直接出现在用户界面上 |
| 5xx | 直接显示 `message` | — |

### 2.5 时间格式

沿用现状，不要改：

| 字段后缀 | 格式 | 例子 |
|---|---|---|
| `*_at`（created_at、updated_at、generated_at…） | ISO 8601 字符串，带时区（推荐 UTC `Z`） | `2026-10-19T05:51:00.000Z` |
| `*_ms`（start_ms、end_ms、due_ms…） | 毫秒时间戳（number） | `1792387860000` |
| 多维表格日期字段（type 5） | 毫秒时间戳（number） | 同上 |

前端统一按用户本地时区显示。

### 2.6 ID

前端把所有 ID 当不透明字符串处理，不解析前缀。现有前缀（`chat_`、`msg_`、`rec_`、`doc_`、`task_`、`evt_cal_`）可以保留。

**机器人的 user_id 固定为 `bot`**，前端用它判断机器人头像和名称（「飞书同学」）。如果要改，请提前通知前端。

### 2.7 跨域

Web 端需要：`access-control-allow-origin`、`access-control-allow-headers: content-type, authorization, x-bot-token`、`access-control-allow-methods: GET, POST, PUT, PATCH, DELETE, OPTIONS`，以及对 `OPTIONS /*` 返回 204。**目前已满足**，上线生产时改成白名单即可。

## 4. 认证与用户

### 4.1 登录 【已有】

`POST /auth/login`

请求：

```json
{ "username": "admin", "password": "admin" }
```

`username` 可以是 user_id，也可以是用户名（现状如此，保持）。

返回 200：

```json
{
  "access_token": "…",
  "refresh_token": "…",
  "expires_in": 7200,
  "user": { "user_id": "admin", "name": "管理员", "email": "admin@lab.cn", "role": "admin" }
}
```

- `expires_in`（秒）**【需修改，P0】**：新增，前端据此在过期前 5 分钟自动刷新
- 失败返回 401 `{"message":"invalid credentials"}`，`message` 文本不要改（前端靠它区分「密码错误」和「登录过期」）

前端位置：`api_client.dart:119`、`login_page.dart:60`

### 4.2 刷新令牌 【新增，P0】

`POST /auth/refresh`（不需要 Authorization 头）

请求：

```json
{ "refresh_token": "…" }
```

返回 200：结构同登录（`access_token`、`refresh_token`、`expires_in`、`user`）。建议每次刷新都轮换 refresh_token。

失败：401 `{"message":"refresh token expired"}`，前端收到后回到登录页。

**同时需要修复（P0）**：令牌载荷加 `typ` 字段（`access` / `refresh`），

- 普通接口和 WebSocket 只接受 `typ=access`
- `/auth/refresh` 只接受 `typ=refresh`

现在 `auth.ts` 的 `verifyToken` 不区分两者，30 天有效的 refresh_token 可以直接调用所有接口。

前端接入后的行为（目前尚未实现）：

1. 登录后保存两个令牌（桌面 / 移动端存到安全存储，Web 端存 localStorage），下次打开自动登录
2. 定时在过期前刷新；任何请求遇到 401（非登录接口）时先尝试刷新一次，成功后重放原请求，失败才回到登录页
3. WebSocket 被以 4401 关闭时同样先刷新再重连

### 4.3 当前用户 【需修改，P1】

`GET /users/me`

返回 200，**与 `GET /users` 列表里的单个用户结构完全一致**（见 4.4）。

现状只返回 `user_id`、`name`、`role`（取自令牌），缺 `email` 等字段。请改为从用户表查询后返回。

前端位置：`api_client.dart:126`

### 4.4 成员列表 【需修改，P1】

`GET /users?keyword=张`

| 参数 | 说明 |
|---|---|
| keyword | 可选，按姓名 / user_id / 邮箱模糊匹配 |

返回 200：

```json
{
  "items": [
    {
      "user_id": "u_zhang",
      "name": "张晓明",
      "email": "zhang@lab.cn",
      "role": "member",
      "avatar_url": null,
      "department": "具身智能组",
      "title": "博士生",
      "phone": null,
      "status_text": null
    }
  ],
  "has_more": false,
  "total": 5
}
```

| 字段 | 类型 | 状态 | 说明 |
|---|---|---|---|
| user_id | string | 已有 | |
| name | string | 已有 | |
| email | string? | 已有 | |
| role | `admin` \| `member` \| `bot` | 已有 | 通讯录按管理员优先排序，显示「管理员」「机器人」标签 |
| avatar_url | string? | 新增 P1 | 头像地址（绝对或相对地址均可）。前端目前一律用名字生成彩色头像，接入后有地址就显示图片 |
| department | string? | 新增 P1 | 名片「部门」。前端目前写死，接入后为空时显示「—」 |
| title | string? | 新增 P2 | 职位 |
| phone | string? | 新增 P2 | |
| status_text | string? | 新增 P2 | 个性签名 / 状态，如「出差中」 |

**机器人账号**：是否出现在列表里都可以。前端对 `user_id == "bot"` 固定显示「飞书同学」，不依赖列表。

前端启动时调用一次，结果缓存为全局成员目录，用于把所有 `*_id` 翻译成姓名和头像（消息发送者、任务负责人、文档创建者、日程参与人、表格人员字段）。成员数在几百以内时不需要分页；如果超过 500 人，请支持 `page_token`，前端会循环拉完。

前端位置：`api_client.dart:128`、`app_state.dart:66`、`contacts_page.dart`

### 4.5 修改个人资料 【新增，P2】

`PATCH /users/me`

```json
{ "avatar_url": "…", "status_text": "出差中", "phone": "…" }
```

返回更新后的用户对象。`name`、`role`、`department` 只允许管理员改（可以另开管理接口，前端暂不做）。

### 4.6 退出登录 【新增，P2】

`POST /auth/logout`，请求 `{ "refresh_token": "…" }`，返回 204。让该 refresh_token 失效。前端退出时调用，失败不影响退出。

## 5. 消息（IM）

### 5.0 数据结构

**Chat（会话）**

```json
{
  "chat_id": "chat_xxx",
  "chat_type": "group",
  "name": "具身智能实验室",
  "member_ids": ["admin", "u_zhang", "bot"],
  "owner_id": "admin",
  "unread_count": 3,
  "last_message": { "…": "Message 对象，没有消息时为 null" },
  "last_read_message_id": "msg_xxx",
  "created_at": "2026-10-19T02:00:00.000Z",
  "updated_at": "2026-10-19T05:40:00.000Z",
  "description": null,
  "kind": "normal"
}
```

| 字段 | 类型 | 状态 | 说明 |
|---|---|---|---|
| chat_id | string | 已有 | |
| chat_type | `p2p` \| `group` | 已有 | |
| name | string? | 已有 | 单聊为 null，前端显示对方姓名；群没有名字时前端用前 3 个成员名拼接 |
| member_ids | string[] | 已有 | 包含自己；机器人为 `bot` |
| unread_count | int | **需修改 P0** | 现在恒为 0，需按「最后已读消息之后、非本人发送的消息数」计算 |
| last_message | Message? | **新增 P0** | 会话列表预览和排序用 |
| last_read_message_id | string? | 新增 P1 | 当前用户在该会话的已读位置 |
| owner_id | string? | 新增 P1 | 群主，决定谁能改群名、移除成员 |
| created_at / updated_at | ISO | 新增 P0 | `updated_at` = 最后一条消息时间（没有消息时 = 创建时间），列表按它倒序 |
| description | string? | 新增 P2 | 群公告 / 简介 |
| kind | `normal` \| `drive` | 新增 P1 | `drive` 表示「我的云盘」存储会话（见 7.5），前端在消息列表里隐藏 |
| pinned / muted | bool | 新增 P2 | 置顶、免打扰 |

**Message（消息）**

```json
{
  "message_id": "msg_xxx",
  "chat_id": "chat_xxx",
  "sender_id": "u_zhang",
  "msg_type": "text",
  "content": { "text": "下午三点开组会" },
  "created_at": "2026-10-19T05:40:00.000Z",
  "updated_at": null,
  "recalled": false,
  "reply_to_message_id": null
}
```

| 字段 | 状态 | 说明 |
|---|---|---|
| message_id / chat_id / sender_id / msg_type / content / created_at | 已有 | |
| updated_at | 新增 P1 | 卡片被回答、消息被编辑时更新 |
| recalled | 新增 P2 | 已撤回；为 true 时 content 可清空，前端显示「xx 撤回了一条消息」 |
| reply_to_message_id | 新增 P2 | 引用回复 |

**content 结构（按 msg_type）**——前端发送和渲染都按下表，请后端校验：

| msg_type | content | 前端发送 | 前端渲染 | 说明 |
|---|---|---|---|---|
| `text` | `{ "text": "…", "mentions": [{"user_id":"u_zhang","name":"张晓明"}] }` | ✅ | ✅ | `mentions` **新增 P2**；现在前端 @ 只是在文本里插入「@姓名 」 |
| `post` | `{ "title": "…", "text": "…" }` | — | ✅ | 机器人富文本；前端也兼容 `content` 为字符串 |
| `image` | `{ "file_key": "…", "file_name": "a.png", "size": 1024, "content_type": "image/png", "width": 800, "height": 600 }` | ✅ | ✅ 缩略图 | `width/height` 新增 P2，用于先占位再加载 |
| `file` | `{ "file_key": "…", "file_name": "报告.pdf", "size": 20480, "content_type": "application/pdf" }` | ✅ | ✅ 文件卡片 | 前端兼容旧字段名 `file_token`、`name` |
| `interactive_card` | 见 5.7 | — | ✅ 可点选项 | 机器人提问卡片 |
| `system` | `{ "text": "张晓明 加入了群聊" }` | — | ✅ 居中灰字 | 由后端生成（建群、加人、退群、改群名） |

发送时后端需校验：`msg_type` 在上表内；`text` 非空且不超过 5000 字；`image` / `file` 的 `file_key` 存在且已上传完成。不合法返回 422。

### 5.1 会话列表 【需修改，P0】

`GET /chats`

| 参数 | 说明 |
|---|---|
| page_size | 可选，默认 100 |
| page_token | 可选 |

返回 200：`{ "items": [Chat…], "has_more": false }`

要求：

1. **只返回当前用户是成员的会话**（已满足）
2. **每个会话带 `last_message`、真实的 `unread_count`、`updated_at`**
3. **按 `updated_at` 倒序**

前端现在的临时做法（`app_state.dart:143`）：拿到会话列表后，对每个会话并行调用一次 `GET /chats/:id/messages?page_size=1` 取最后一条消息，再在本地排序；未读数完全靠前端在内存里累计（`app_state.dart:119`）。后端做完后前端会删掉这两段。

### 5.2 创建会话 【需修改，P1】

`POST /chats`

请求：

```json
{
  "chat_type": "group",
  "name": "论文讨论组",
  "member_ids": ["u_zhang", "u_li"]
}
```

| 字段 | 说明 |
|---|---|
| chat_type | **新增**，`p2p` 或 `group`。不传时沿用现在的推断规则（总人数 > 2 为群），保证兼容 |
| name | 可选；群聊名称 |
| member_ids | 不含自己也可以，后端自动加上自己并去重 |
| kind | 可选，`drive`，见 7.5 |

规则：

- `chat_type=p2p`：`member_ids` 必须恰好 1 个人（不是自己）。**如果两人之间已有单聊，直接返回已有会话（200）**，否则新建（201）。现在每调用一次就多建一个单聊，前端只能在本地查重（`app_state.dart:237`）
- `chat_type=group`：允许只有自己 + 1 人；建群成功后后端插入一条 `system` 消息「xx 创建了群聊」
- 返回 Chat 对象（结构同 5.0）
- 新会话要通过 WS 推送给其他成员（`chat.created`，见第 6 节），否则对方要等第一条消息到了才能看到这个群

前端位置：`api_client.dart:138`；单聊入口在通讯录名片「发消息」、消息页「+」，建群入口在消息页「+ → 创建群组」

### 5.3 会话详情与群管理 【新增，P1】

| 接口 | 说明 | 权限 |
|---|---|---|
| `GET /chats/:chat_id` | 返回单个 Chat | 成员 |
| `PATCH /chats/:chat_id` | 请求 `{ "name": "新群名", "description": "…" }`，返回 Chat | 群主或管理员 |

### 5.4 消息历史 【需修改，P0】


### 5.7 机器人卡片 【需修改，P0】

**卡片消息 content（机器人发送，`src/pal/classmateos-adapter.ts:147`）：**

```json

  "card_id": "card_1729311060_ab12cd",
  "question": "这周组会改到周四下午可以吗？",
  "options": ["可以", "不行", "再商量"],

```

- `options` 可以是字符串数组，也可以是 `[{ "label": "可以", "value": "yes" }]`。前端显示 `label`（没有时显示 `value`），**回答时回传的 `action` 是显示的文字**（即 `label`），不是 `value`。机器人大脑目前按文字匹配答案，所以建议继续用字符串数组；如果以后要用 `value`，请通知前端改为回传 `value`
- 前端也兼容用 `title` 代替 `question`
- **`answer` 新增 P0**：未回答为 null；回答后为

```json
{ "user_id": "admin", "action": "可以", "answered_at": "2026-10-19T05:51:00.000Z" }
```

**回答卡片** `POST /cards/:card_id/actions` 【已有，需修改】

请求：

```json
{ "action": "可以", "form_values": {} }
```

返回 202 `{ "accepted": true }`（保持）。

需要新增的行为：

1. 找到 `content.card_id == card_id` 的消息，校验当前用户是该会话成员，否则 403
2. 已经回答过 → 返回 **409** `{ "message": "这张卡片已经回答过了", "answer": {…} }`，不再发布 `card.action` 事件
3. 未回答 → 把 `answer` 写回消息 content、更新 `updated_at`，发布 `card.action`（给机器人大脑，已有），并向会话成员推送 `message.updated`（带完整消息）
4. 卡片超时（机器人不再等待）时，机器人可以通过 bot 网关把卡片标记为过期：`content.expired = true`（P2），前端显示「已过期」并禁用选项

前端现状：回答结果只记在内存（`app_state.dart:51` `cardAnswers`），重启 App 后卡片又能重复回答。后端做完后前端改为读 `content.answer`。

## 6. 实时事件（WebSocket）

### 6.1 连接 【已有，需修改】

`GET /api/v1/events/ws?token=<access_token>&since=<event_id>`

- `token`：access_token（浏览器无法设置自定义头，所以走 query）
- `since`：**新增 P1**，断线重连时带上收到的最后一个 `event_id`，后端补发之后该用户有权看到的事件（bot WS 已经有 `replay`，复用即可）；`since` 太旧无法补发时，后端发送一帧 `{"event_type":"resync.required"}`，前端收到后重新拉会话列表

关闭码：

| 关闭码 | 含义 | 前端动作 |
|---|---|---|
| 4401 | 令牌无效或过期（已有） | 刷新令牌后重连；刷新失败回登录页 |
| 4403 | 账号被禁用（新增 P2） | 回登录页 |
| 其他 / 网络断开 | — | 3 秒后重连（已实现），重连前先补拉会话列表 |

心跳 **【新增 P1】**：后端每 30 秒发送 WS ping 帧（或文本帧 `{"event_type":"ping"}`）。前端接入后：60 秒没收到任何帧就主动断开重连；同时每 30 秒发送文本帧 `{"type":"ping"}`，后端可回 `{"event_type":"pong"}` 或忽略，**不要因收到客户端文本帧而断开连接**。（前端目前不发也不检查心跳。）

### 6.2 帧格式

每帧一个 JSON 对象，沿用 BotEvent 结构并扩展：

```json
{
  "event_id": "evt_xxx",
  "event_type": "message.receive",
  "created_at": "2026-10-19T05:51:00.000Z",
  "message": { "…": "Message" },
  "chat": { "…": "Chat" },
  "read": { "chat_id": "chat_xxx", "user_id": "admin", "message_id": "msg_xxx" },
  "card_action": { "…": "仅 bot WS 使用" }
}
```

### 6.3 事件类型

「前端动作」列中，`message.receive` 是现有行为，其余为后端上线后前端会做的处理。

| event_type | 状态 | 携带字段 | 推送对象 | 前端动作 |
|---|---|---|---|---|
| `message.receive` | 已有 | message | 会话全部成员（含发送者自己） | 追加消息、更新会话预览、非当前会话未读 +1 |
| `message.updated` | 新增 P0 | message（完整） | 会话全部成员 | 按 message_id 替换（卡片已回答、撤回、编辑） |
| `message.read` | 新增 P0 | read | 本人其他设备（P2：会话成员） | 清除该会话未读 |
| `chat.created` | 新增 P1 | chat | 新会话全部成员 | 会话列表插入 |
| `chat.updated` | 新增 P1 | chat | 会话全部成员 | 更新群名等 |
| `chat.member_added` | 新增 P1 | chat | 会话全部成员（含新成员） | 更新成员；新成员插入会话 |
| `chat.member_removed` | 新增 P1 | chat + `user_id` | 会话全部成员 + 被移除者 | 被移除者从列表删除该会话 |
| `resync.required` | 新增 P1 | — | — | 重新拉会话列表 |
| `ping` | 新增 P1 | — | — | 忽略 |
| `task.assigned` | 新增 P2 | task | 被指派人 | 任务角标、系统通知 |
| `calendar.invited` | 新增 P2 | event | 被邀请人 | 日历角标、系统通知 |

**过滤规则**：用户 WS 只推送当前用户有权看到的事件（现状对 `message.receive` 按会话成员过滤，新事件同理）。`card.action` 不推给用户 WS。

前端位置：`app_state.dart:77`（连接与重连）、`app_state.dart:119`（处理消息）

### 7.3 获取下载地址 【需修改，P1】

`GET /files/:file_key/download-url?disposition=inline`

| 参数 | 说明 |
|---|---|
| disposition | 新增，`inline`（默认，图片预览）或 `attachment`（下载） |

返回 200：`{ "download_url": "…", "expires_in": 600 }`

要求：

1. **`expires_in` 不小于 300 秒**：前端会把下载地址缓存 4 分钟，用来反复显示同一张图片（`app_state.dart:282`）
2. `GET {download_url}` 返回时：
   - `Content-Type` 用上传时记录的类型（现在一律 `application/octet-stream`，浏览器无法预览图片和 PDF）
   - `Content-Disposition: inline` 或 `attachment; filename*=UTF-8''<URL 编码的原始文件名>`（现在没有这个头，下载地址以 `/content` 结尾，浏览器把文件存成 `content`；`file_key` 里的中文也被替换成了 `_`，所以文件名必须用 7.1 记录的原始 `file_name`）
   - 支持 `Range` 请求（P2，大文件 / 视频）
3. 权限（P1）：只有能看到这个文件的人可以拿下载地址——文件所在会话的成员、多维表格记录的可见者、文件上传者本人。其他人返回 404

前端位置：`api_client.dart:202`；点文件卡片、云盘下载按钮、表格附件时调用，然后用系统浏览器打开地址。

前端现状：只请求第一页 500 条（`bitable_page.dart:238`），搜索、排序都在前端做。P1 前端会按 `page_token` 循环加载；后端支持 `keyword` 后，搜索改为服务端。

### 8.3 单条记录 【已有】

### 8.4 新增记录 【已有】

### 8.5 修改记录 【已有】

- 只提交改过的字段
- **值为 `null` 表示清空该字段**（前端在用户删掉某个值时发 null，后端必须支持，现状已支持）

### 8.6 删除记录 【已有】

## 14. 验收清单

后端完成后可以按下面逐项自测（`$T` 为 admin 的 access_token，`$T2` 为另一个普通成员的 token）：

**P0**

- [ ] 非会话成员 `GET /chats/{别人的会话}/messages` 返回 403；`POST` 同样 403
- [ ] A 给 B 发 3 条消息后，B 的 `GET /chats` 里该会话 `unread_count = 3`、`last_message` 是第 3 条、该会话排在第一位
- [ ] B 调 `POST /chats/:id/read` 后，`unread_count = 0`；B 的另一个 WS 连接收到 `message.read`
- [ ] 一个会话 120 条消息：`page_size=50` 返回 50 条且 `has_more=true`；用最后一条的 id 作 `before_message_id` 再取，3 页取完，不重不漏
- [ ] 回答卡片后，`GET` 消息里该卡片 `content.answer` 有值；再次回答返回 409；会话成员的 WS 收到 `message.updated`
- [ ] 用 refresh_token 直接当 Bearer 调 `GET /users/me` 返回 401
- [ ] `POST /auth/refresh` 返回新令牌；过期的 access_token 连 WS 被 4401 关闭
- [ ] 后端重启后数据仍在（接 PostgreSQL）

**P1**

- [ ] `GET /users/me` 与 `GET /users` 中本人的字段完全一致
- [ ] 对同一个人调两次 `POST /chats {chat_type:"p2p"}`，返回同一个 chat_id
- [ ] `POST /chats {chat_type:"group", member_ids:[1 个人], name:"x"}` 返回 `chat_type = "group"`
