# 多维表格：新建数据表接口需求

前端已加入“新建数据表”入口；在后端实现本接口前，提交时会提示“当前后端尚未开放新建数据表接口”，并保留填写内容。

## 1. 新增接口

`POST /api/v1/tables`

需要登录。建议权限：所有已登录且未禁用用户都可以创建；如需只允许管理员，返回 403，前端会显示后端中文 `message`。

### 请求

```json
{
  "name": "设备借用",
  "description": "记录实验室设备借用情况",
  "primary_field": "name",
  "client_request_id": "table_1760873000000000",
  "fields": [
    { "field_name": "name", "title": "名称", "type": 1, "required": true },
    { "field_name": "field_1", "title": "状态", "type": 3, "required": false, "options": ["空闲", "借出"] },
    { "field_name": "field_2", "title": "借用人", "type": 11, "required": true }
  ]
}
```

| 字段 | 必填 | 规则 |
|---|---|---|
| `name` | 是 | 去掉首尾空格后 1–60 字；同一工作区内建议唯一，大小写不敏感 |
| `description` | 否 | 最多 500 字 |
| `primary_field` | 是 | 必须是 `fields` 中的 `field_name`，且该字段类型必须为文本 `1`、必填 |
| `client_request_id` | 否 | 同一用户 24 小时内重复提交同一个 ID 时，返回第一次创建的表，不能重复建表 |
| `fields` | 是 | 1–30 个字段 |
| `fields[].field_name` | 是 | 机器字段名，正则 `^[a-z][a-z0-9_]{0,63}$`，同表唯一 |
| `fields[].title` | 是 | 中文显示名，1–40 字，同表唯一 |
| `fields[].type` | 是 | 支持 `1` 文本、`2` 数字、`3` 单选、`4` 多选、`5` 日期、`7` 复选框、`11` 人员、`15` 超链接、`17` 附件 |
| `fields[].required` | 否 | 默认 false |
| `fields[].options` | 单选/多选必填 | 1–50 项，每项 1–40 字，去空格后不得重复；其它类型忽略或返回 422 均可，建议返回 422 |

暂不支持在新建时创建关联字段 `18`。

## 2. 成功返回

返回 `201 Created`，响应体与 `GET /api/v1/tables` 中单个表对象结构一致：

```json
{
  "key": "tbl_8f3a2c",
  "name": "设备借用",
  "description": "记录实验室设备借用情况",
  "icon": "table",
  "primary_field": "name",
  "created_by": "ou_admin",
  "created_at": "2026-10-19T11:22:00.000Z",
  "updated_at": "2026-10-19T11:22:00.000Z",
  "fields": [
    { "field_name": "name", "title": "名称", "type": 1, "required": true },
    { "field_name": "field_1", "title": "状态", "type": 3, "required": false, "options": ["空闲", "借出"], "option_colors": { "空闲": "green", "借出": "orange" } },
    { "field_name": "field_2", "title": "借用人", "type": 11, "required": true }
  ]
}
```

- `key` 由后端生成，不能与现有内置表重复，创建后不可变，前端会直接用于 `/tables/:table_key/records`。
- 幂等命中时可返回 `200 OK`，响应体相同。
- 单选、多选的 `option_colors` 可由后端自动分配，前端可识别 `blue`、`green`、`orange`、`red`、`purple` 等现有颜色名。

## 3. 错误返回

沿用现有格式：

```json
{
  "message": "字段校验失败",
  "code": "VALIDATION_FAILED",
  "errors": [{ "field": "fields[1].options", "message": "至少填写一个选项" }]
}
```

| 状态码 | code | 场景 |
|---|---|---|
| 401 | `UNAUTHORIZED` | 未登录或令牌无效 |
| 403 | `FORBIDDEN` | 没有建表权限 |
| 409 | `TABLE_NAME_EXISTS` | 数据表名称重复，message 用中文 |
| 422 | `VALIDATION_FAILED` | 参数格式或字段配置不正确 |

## 4. 与现有接口的联动

1. `GET /api/v1/tables` 必须返回新表；排序建议内置表在前，自定义表按创建时间倒序或正序，保持稳定即可。
2. 新表必须立即可用于现有记录接口：
   - `GET /api/v1/tables/:table_key/records`
   - `POST /api/v1/tables/:table_key/records`
   - `GET /api/v1/tables/:table_key/records/:record_id`
   - `PATCH /api/v1/tables/:table_key/records/:record_id`
   - `DELETE /api/v1/tables/:table_key/records/:record_id`
3. 记录校验应使用新表的字段定义，包括必填、类型、选项、人员 ID 和附件引用。
4. 数据表定义和记录都需要持久化；接入 PostgreSQL 时，重启后新表和记录仍存在。
5. 当前 `resolveTable` 依赖内置表定义；需要改为“内置表 + 数据库中的自定义表”统一解析。

## 5. 验收清单

- [ ] 登录用户提交合法请求，返回 201，响应带 `key` 和完整字段定义。
- [ ] 同一 `client_request_id` 重复提交，不产生第二张表。
- [ ] `GET /tables` 能看到新表，字段 `title`、`type`、`required`、`options` 与创建时一致。
- [ ] 新表可新增、编辑、删除记录，并按字段定义返回中文校验错误。
- [ ] 主字段不存在、不是文本、不是必填时返回 422。
- [ ] 字段名不合法、字段名/显示名重复、单选多选缺选项时返回 422。
- [ ] 表名重复返回 409 `TABLE_NAME_EXISTS`。
- [ ] PostgreSQL 模式下重启后，新表和记录仍存在。
