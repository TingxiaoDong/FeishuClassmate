## 3. 消息接口

### 3.1 消息对象新增字段

```json
{
  "message_id": "om_1", "chat_id": "oc_lab", "sender_id": "ou_admin", "msg_type": "text",
  "content": {"text": "…"},
  "read_count": 2, "member_count": 3,
  "thread_root_id": null, "also_send_to_chat": false,
  "thread": {"reply_count": 2, "last_reply_at": "2026-10-20T01:00:00Z", "participants": ["ou_zhang"], "followed": true},
  "reactions": [{"emoji": "THUMBSUP", "count": 2, "user_ids": ["ou_demo", "ou_zhang"], "reacted_by_me": false}],
  "forwarded_from": {"chat_name": "具身智能实验室", "sender_id": "ou_demo"},
  "urgent": {"user_ids": ["ou_demo", "ou_chen"], "ack_user_ids": ["ou_demo"]}
}
```

| 字段 | 说明 | 缺失时 |
|---|---|---|
| `read_count` / `member_count` | **只在自己发的消息上返回**；`member_count` 不含发送人 | 不显示回执 |
| `thread_root_id` | 话题回复才有 | 普通消息 |
| `also_send_to_chat` | 话题回复同时发到群 | false |
| `thread` | 只在根消息上返回 | 不显示话题摘要 |
| `thread.followed` | **补充约定**：当前用户是否关注了这个话题，用于话题面板「关注话题 / 已关注」 | 显示「关注话题」 |
| `reactions` | 只返回 `count > 0` 的 | 空 |
| `forwarded_from` | 单条转发来的消息 | 不显示来源 |
| `urgent` | **补充约定**：只给发送人看，用于「加急 · N 人未确认」 | 不显示 |

消息 ID 前端当作不透明字符串，不拆解。

### 3.2 已读回执（R-IM-01）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/chats/:chat_id/messages` | 自己发的消息带 `read_count`、`member_count` |
| GET | `/messages/:message_id/read-users` | `{read: [user_id], unread: [user_id]}`，只有发送人能查，其他人 403 |
| WS | `message.read` | `{chat_id, user_id, last_read_message_id}`，**推给会话全体成员** |

**和需求文档的差异**：需求文档建议前端收到 `message.read` 后自己给 `read_count + 1`。前端没有这样做，而是收到事件后防抖 500ms，**重新取最近一页消息，用后端的 `read_count` 覆盖**。原因：同一个人多端已读、重连后补发事件都会让前端累加出错。请后端保证 `read_count` 是准确的实时值。

- 超过 100 人的群不显示回执（前端判断 `member_count > 100`）。
- 已读名单的「未读」里有「一键加急未读成员」（需要 `message.urgent` 开关）。

### 3.3 话题（R-IM-02）

| 方法 | 路径 | 前端实际发送 / 期望返回 |
|---|---|---|
| POST | `/chats/:chat_id/messages` | 话题回复多带 `thread_root_id`，勾了「同时发送到群」时带 `also_send_to_chat: true`；普通消息**不带**这两个字段 |
| GET | `/chats/:chat_id/messages` | 默认不返回话题回复（`also_send_to_chat` 的除外） |
| GET | `/messages/:message_id/thread?page_size=50&page_token=` | `{items, has_more, page_token}`，按时间正序；前端会一直取到 `has_more: false`，游标缺失或重复时报错 |
| POST / DELETE | `/messages/:message_id/thread/follow` | 关注 / 取消关注 |
| PATCH | `/chats/:chat_id` | `{thread_mode: true \| false}`，只有群主和管理员能改，其他人请返回 403 |

- 回复话题时请推 `message.receive`（带 `thread_root_id`），并对根消息推 `message.updated`（带新的 `thread`）。前端根据 `thread_root_id` 把它放进话题面板，不放进主会话。
- 话题回复不更新会话列表的「最后一条消息」（`also_send_to_chat` 除外）。
- **补充约定**：会话对象带 `thread_mode`、`thread_unread_count`（当前用户在这个会话里有新回复的话题数），会话列表显示「话题 N」。
- **补充约定**：不允许在话题回复里再开话题，请返回 422。
- 话题模式群：输入框提示「发布新话题」，每条消息都能展开话题；`also_send_to_chat` 在话题模式群里没有意义，前端不显示这个勾选框。需求文档说话题模式的主界面是「话题卡片列表」，前端这次**仍用消息流 + 话题摘要**的样式，没有单独做卡片列表。

### 3.4 表情回应（R-IM-03）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/messages/:message_id/reactions` | `{emoji: "THUMBSUP"}` |
| DELETE | `/messages/:message_id/reactions/:emoji` | 取消自己的 |

- **补充约定**：两个接口都请**返回更新后的消息对象**，前端直接用它刷新；同时推 `message.updated` 给其他人。不返回也行，前端会等 `message.updated`。
- 前端认识的 key：`THUMBSUP DONE OK HEART LAUGH CLAP FIRE EYES SURPRISED CRY PRAY MUSCLE PARTY THINKING ROCKET SMILE`。不认识的 key 原样显示文字。

### 3.5 转发（R-IM-04）

```
POST /messages/forward
{"message_ids": ["om_1", "om_2"], "chat_ids": ["oc_2"], "mode": "single" | "merge", "note": "看看", "client_request_id": "c_..."}
→ {"items": [新发出的消息...]}
```

- `chat_ids` 最多 10 个，前端已限制；超出请返回 422。
- `note` 为空时前端不带这个字段。**补充约定**：`client_request_id` 用于防止重复提交，同一个 ID 请只执行一次。
- 合并转发：`msg_type: "merge_forward"`，`content: {title, messages: [消息快照]}`。前端卡片显示标题和前 3 条，点开是只读列表。快照里请带 `sender_id`、`msg_type`、`content`、`created_at`。
- 转发图片、文件后接收方要能下载（需求文档已写，请后端补文件引用）。
- 多选底部栏只做了「逐条转发」「合并转发」；需求文档里的「删除（仅自己）」「收藏」没有放在多选里。

### 3.6 加急（R-IM-05）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/messages/:message_id/urgent` | `{user_ids, type: "app" \| "push"}`；每人每条一次，太频繁返回 429；只能加急自己发的消息 |
| POST | `/messages/:message_id/urgent/ack` | 被加急的人点「知道了」 |
| GET | `/messages/urgent/pending` | **补充约定（新增）**：我还没确认的加急 `{items: [{message_id, chat_id, from_user_id, preview?}]}`。App 启动和 WS 重连后调用，否则离线期间的加急横幅会丢 |
| WS | `message.urgent` | `{message_id, chat_id, from_user_id, preview?}`；**补充约定**：带上 `preview`（消息文字摘要），横幅直接显示 |
| WS | `message.urgent_acked` | **补充约定（新增）**：`{message_id, user_id}`，推给本人的其他端（让其他设备的横幅一起消失）和发送人（更新「N 人未确认」） |

- 前端被加急后：顶部红色横幅（多条时显示「还有 N 条」）、会话列表头像角标「急」和「加急」标签。
- `POST /urgent` 请返回更新后的消息（带 `urgent`），前端用它刷新「加急 · N 人未确认」。

## 4. 全局搜索（R-SR-01）

### 4.1 接口

```
GET /api/v1/search?q=标定&types=user,chat,message,doc,wiki,record,task,event&page_size=3
```

```json
{"groups": [
  {"type": "message", "total": 5, "page_token": "3",
   "items": [{"id": "om_9", "title": "…<em>标定</em>…", "snippet": "", "updated_at": "…",
              "extra": {"chat_id": "oc_lab", "sender_id": "ou_demo", "thread_root_id": null}}]}
]}
```

- 综合页：`types` 是全部类型，`page_size=3`；每组显示 3 条，`total > 3` 或有 `page_token` 时显示「查看更多（total）」。
- 分类页：`types` 只有一个，`page_size=20`，「加载更多」带 `page_token`。
- 没有知识库开关时，`types` 不带 `wiki`。
- **请把 `total` 返回准确**（「查看更多」里显示的数字）。没有 `total` 时前端用本页条数。
- **兼容提醒**：迭代 2 的知识库搜索也用 `GET /search`（带 `scope=wiki`）。全局搜索**一定会带 `types`**，后端可以据此区分，两种调用都请继续支持。

### 4.2 各类型的 `extra` 和跳转（补充约定）

| type | `id` | 需要的 `extra` | 前端点击后 |
|---|---|---|---|
| `user` | user_id | — | 打开和他的单聊（没有就新建） |
| `chat` | chat_id | — | 打开群 |
| `message` | message_id | `chat_id`（必需）、`sender_id`；话题回复带 `thread_root_id` | 打开会话，往前翻页找到这条（最多 10 页）并高亮 3 秒；话题回复会打开话题面板 |
| `doc` | doc_id | `owner_id` | 打开文档 |
| `wiki` | node_id | `space_id`、`doc_id`、`owner_id` | 打开知识库页面 |
| `record` | record_id | `table_key`（必需）、`table_name` | 打开表格并定位记录 |
| `task` | task_id | — | 打开任务详情（用 `GET /tasks/:id`） |
| `event` | event_id | `start_ms`（必需） | 日历翻到那一周并打开详情 |

### 4.3 筛选参数（补充约定，需求文档只写了「有哪些筛选」，没写参数名）

| 分类 | 参数 |
|---|---|
| 消息 | `chat_id`、`sender_id`、`start_ms` |
| 云文档 / 知识库 | `owner_id`、`start_ms`（按更新时间） |
| 多维表格 | `table_key` |

时间筛选是「近 7 天 / 近 30 天 / 近一年」，前端只发 `start_ms`；`end_ms` 预留，暂时不发。

### 4.4 其他

- 高亮只认 `<em>…</em>`，其他标签原样当文字显示（不会当 HTML 执行）。
- 结果必须按权限过滤。
- 中文分词：测试数据模式是简单实现（连续中文按两个字一组切），只用来自测，**正式效果以后端为准**。
- 最近搜索存在前端本地，最多 20 条，不需要接口。
- 最近访问：`GET /recent?page_size=10` → `{items: [{type, id, title, visited_at, extra?}]}`，`type` 是 `doc / wiki / table / record`。
- `page_token` 前端当不透明字符串；测试数据模式用的是数字偏移。

## 6. 收藏、Pin、链接预览（R-IM-06、R-IM-07）

### 6.1 功能开关
新增 `message.favorite`、`message.pin`、`message.link_preview`、`message.rich_text`，缺失为 false。

### 6.2 收藏
- `POST /messages/:message_id/favorite` 收藏（幂等），`DELETE` 同路径取消，成功允许 204。
- `GET /favorites?page_size=30&page_token=` 返回 `{items:[{favorite_id,message,chat_name,created_at}],has_more,page_token}`。`message` 是消息对象。
- 桌面入口在头像菜单「我的收藏」，移动端工作台也有入口。列表可取消收藏、跳回原会话。
- 当前列表跳转尚不专门定位话题里的收藏回复；普通消息最多回溯 10 页。消息删除、退出群后的收藏可见性必须由后端校验，不能泄露正文。

### 6.3 Pin
- `GET /chats/:chat_id/pins` → `{items:[{message,pinned_by,pinned_at}]}`。
- `POST /chats/:chat_id/pins/:message_id` 固定，`DELETE` 同路径取消；成功允许 204。
- 最多 10 条，超出建议 409 `PIN_LIMIT`；重复固定幂等。
- 会话对象新增 `pinned_message_ids: [message_id]`；变化推 `chat.updated`，带更新后的数组。
- 顶部显示固定条，点开可跳转或取消固定。当前前端按“群成员可固定”展示按钮；若后端限制管理员操作，需补权限字段并在联调时调整，后端必须独立鉴权。

### 6.4 富文本与链接
- 开启 `message.rich_text` 后，输入加粗、列表、引用、标题、代码语法时发 `post`、`content:{markdown}`；没有语法仍发普通文本。存在 @ 成员时目前仍发送普通文本，以保留提及。
- 外部链接：后端在 `content.link_previews` 返回 `[{url,title,description}]`，前端展示卡片，不自行抓网页。后端需防范 SSRF、限流并过滤不安全协议。
- 内部分享链接建议使用当前服务器的 `/app/docs/:doc_id`、`/app/wiki/:node_id`、`/app/tasks/:task_id`、`/app/tables/:table_key/records/:record_id`；也支持 `classmateos://docs/:doc_id` 等写法。此格式是新增约定，请后端确认。
- 卡片取标题使用已有的 `GET /docs/:id`、`GET /wiki/nodes/:id`、`GET /tasks/:id`；记录卡片另需 `GET /tables/:key/records/:id` 返回 `{fields}`。后端尚未支持时卡片显示加载失败，不伪造标题。
- 内部卡片当前展示标题和类型；没有正文摘要。每条消息内部、外部卡片各最多 3 个。权限不足显示提示；点击仍需后端鉴权。
- 涉及文件：`pages/message_more.dart`；新测试 `phase2_iter4_more_test.dart` 共 6 个。

### 6.5 与原需求的明确差异
- 话题群仍用消息流 + 话题摘要，不是独立卡片布局。
- 多选仅提供逐条、合并转发，未实现多选收藏和“仅自己删除”。
- 未对真实后端、手机真机推送、搜索性能和权限隔离做验收。
- Markdown 属于输入语法识别，不是所见即所得编辑器；内部链接摘要未实现。
