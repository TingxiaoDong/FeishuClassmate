## 3. 请后端确认 / 补充的约定

需求文档没写清楚、前端先按下面的方式实现的地方。

### 3.1 文档与权限

1. **`Doc` 对象新字段**：前端读 `permissions`、`my_role`、`owner_id`、`folder_id`、`starred`、`last_viewed_at`、`deleted_at`，以及知识库页面的 `wiki_space_id`、`wiki_node_id`（需求文档没列这两个；前端用来判断「移入知识库」时排除已在知识库里的文档）。
2. **列表查询**：`GET /docs?scope=mine&folder_id=` 不带 `folder_id` 时，前端期望只返回**根目录**下的文档（不是全部）。
3. **删除**：`DELETE /docs/:id` 进回收站，`DELETE /docs/:id?permanent=true` 彻底删除。文件夹删除时里面的文档一起进回收站。
4. **申请权限**：前端在申请弹窗里让用户选 `viewer / commenter / editor`，并带备注 `note`。所有者在通知里处理（`POST .../access-requests/:id/approve|reject`），通知的 `target` 请带 `{ type: "access_request", doc_id, request_id }`；前端通知面板目前只跳到文档，**一键同意按钮还没做**（等后端定格式）。
5. **知识库页面的权限接口**：`GET /docs/:id/permissions` 对知识库页面请返回 `inherited_from: { space_id, name }`，前端据此只显示「继承自 XX 空间」和链接分享开关。
6. **WS 事件**：打开文档时订阅 `doc:<doc_id>`，处理 `doc.comment_changed`（重新拉评论）和 `doc.permission_changed { doc_id, user_ids }`（`user_ids` 为空或包含自己时重新拉文档，权限变化时提示「你的权限已变更」）。`doc.permission_changed` 是前端额外约定的，需求文档里只有关闭码 4410。

### 3.2 评论锚点（重要）

需求文档要求锚点用 Yjs `RelativePosition`。**前端编辑器目前不是 Yjs**（Markdown 文本框 + 自动保存），拿不到 RelativePosition，所以现在发的是：

```json
"anchor": { "offset": 128, "length": 15 }
```

加上 `quote`（原文）。前端高亮时按 `quote` 在正文里查找；找不到时评论显示「原文已删除」。后端请**原样保存** `anchor`，不要校验格式。以后前端接入 Yjs 再换成 `yjs_relative_start / end`。

### 3.3 历史版本

- 列表项读 `version_id`、`name`、`created_by`、`created_at`、`added`、`removed`。
- `GET /docs/:id/versions/:version_id` 返回 `{ markdown }`。
- 还原后前端会重新拉文档。还原前如果有未保存的修改，前端会提醒用户会被覆盖。

### 3.4 图片和附件

- 上传：`POST /files/upload-url` 多传 `ref: { type: "doc", id: doc_id }`。
- 图片写 `![文件名](cos-file://file_key)`；附件写 `[📎 文件名](cos-file://file_key?name=xxx&size=123)`，查询参数用来显示附件卡片，请后端不要解析。
- 渲染时调 `GET /files/:file_key/download-url`，前端缓存 40 分钟，所以**签名地址有效期请不少于 1 小时**。
- 粘贴截图、拖拽文件进编辑区**还没接**（Flutter 桌面端读剪贴板图片需要额外插件），现在只有工具栏按钮。

### 3.5 知识库

1. **列表**：`GET /wiki/spaces/:id/nodes?parent_id=` 返回 `{ items, has_more }`；前端按返回顺序显示，不自己排序。
2. **移动**：`POST /wiki/nodes/:id/move { space_id, parent_id, after_node_id }`，`after_node_id` 为 `null` 表示放到新父节点的**第一个**。
3. **复制**：`POST /wiki/nodes/:id/copy { with_children }`，返回新节点（前端会直接打开它）。
4. **最近 / 收藏**：节点上请带 `space_name` 和 `starred`，前端卡片上显示空间名。
5. **搜索**：`GET /search?scope=wiki&space_id=&q=` 每项读 `type`、`id`（或 `node_id`）、`title`、`snippet`（或 `highlight`，用 `<em>` 包关键词）、`space_id`、`space_name`、`path`。
6. **WS**：打开空间时订阅 `wiki:<space_id>`。`wiki.node_changed` 前端读 `space_id`、`node_id`、`action`（`created / updated / moved / deleted`）；跨空间移动时请带 `to_space_id`。另外前端处理了 `wiki.space_changed { space_id }`（空间设置或成员变化），收到后重新拉空间，拉不到就退回首页。
7. **通知跳转**：`target: { type: "wiki", id: node_id }`，前端调 `GET /wiki/nodes/:id` 拿到 `space_id` 后打开空间、展开祖先并打开页面。
8. **空间删除**：前端只给 `admin` 显示；删除后里面的页面怎么处理（进回收站还是直接删）请后端定，前端提示文字目前是「无法恢复」。

### 3.6 协同头像

- 需求文档说这一条纯前端能做。前端连 `/api/v1/docs/:doc_id/collab?token=`，**只发 awareness（消息类型 1）、不发 sync**，所以不会改动正文。
- awareness 里放 `{ user_id, name, color, cursor: { line } }`。`cursor` 现在是**行号**，不是 RelativePosition（原因同 3.2），所以只显示头像和「正在编辑第几行」，没有画光标。
- 前端加了一个开关 `doc.presence` 控制这个功能，后端确认协同 WS 对只读用户也允许连接（只读连接只转发 awareness）后再打开。

### 3.7 多维表格

1. **表权限**：`GET/PUT /tables/:key/permissions`，前端用字段 `visibility`（`all | members`）+ `members`。需求文档写的是「结构同云文档」，但云文档用的是 `link_share`，前端按表的语义用了 `visibility`，请确认。
2. **侧边栏**：没有查看权限的表，请后端在 `GET /tables` 里直接不返回。
3. **表上的 `permissions`**：前端根据 `can_manage` 显示「重命名」「权限设置」，根据 `can_delete`（或 `can_manage`）和 `builtin == false` 显示「删除」。
4. **复制表**：`POST /tables/:key/copy { name, with_records }`，表名重复时返回 409 `TABLE_NAME_EXISTS`，前端显示在输入框下面。
5. **修改记录**：每项读 `operator_id`、`at`、`changes[]`，前端额外读可选的 `action`（`created / updated / deleted`），有它时显示「创建了记录」等。
6. **记录评论**：`content` 用 2.4 的提及结构；被 @ 的人收到 `record.mention` 通知，`target` 请带 `table_key` 和 `id`。
