## 3. 请后端确认 / 补充的约定

需求文档没写清楚、前端先按下面的方式实现的地方。如果后端想用别的写法，告诉前端改。

### 3.1 字段

1. **选项改名**：文档要求改名时同步已有记录，但没说后端怎么知道是改名而不是“删一个、加一个”。前端在 `PATCH /tables/:key/fields/:field` 里多传一个：
   ```json
   "option_renames": { "进行中": "开发中" }
   ```
   没出现在 `options` 里、也不在 `option_renames` 里的旧选项按“删除”处理。
2. **删除字段的 `base_version`**：DELETE 不带 body，前端放在 query：`DELETE /tables/:key/fields/:field?base_version=8`。
3. **取单张表**：别人改了字段（收到 `table.schema_changed`）或冲突后，前端调 `GET /tables/:table_key` 取最新定义，返回格式和 `GET /tables` 里的单个表对象一样。文档里没有列这个接口，请一起加上。
4. **字段的 `builtin`**：前端优先读字段上的 `builtin`；没有时按所在表的 `builtin` 判断（内置表的字段都当内置字段）。内置表里用户新增的字段请返回 `builtin: false`，否则前端不会显示删除按钮。
5. **主字段**：按表的 `primary_field` 判断；不能删、不能改类型。
6. **`FIELD_IN_USE`**：前端直接显示后端的 `message`，请在 message 里写清楚是被哪个视图或关联引用的。

### 3.2 视图

1. **调整顺序**：`PUT /tables/:key/views/order` 的 body 前端写成 `{ "view_ids": [...] }`（文档没写字段名）。
2. **PATCH 可改 `personal`**：「设为个人视图 / 设为公共视图」用 `PATCH /views/:id { "personal": true, "version": n }`。设为个人时 `owner_id` 设为操作人。
3. **新建视图的权限**：没有 `can_edit` 的成员点「新建视图」或「复制视图」时，前端自动建成个人视图（`personal: true`），请后端允许。
4. **`config` 原样保存**：前端不认识的配置项（如 `calendar`）会原样回传，请后端不要丢掉。
5. **筛选值的格式**（前端发的，后端计算时请按这个解析）：
   - `is` / `is_not`：数组，元素都是字符串。单选、多选是选项文字；人员是 user_id；复选框是 `"true"` / `"false"`；日期是当天 0 点的毫秒数（字符串），按天比较；数字是数字字符串
   - `contains` / `not_contains`：字符串
   - `gt` / `gte` / `lt` / `lte`：数字（日期为毫秒）
   - `is_empty`、`is_not_empty`、`today`、`this_week`、`last_7_days`、`this_month`：不带 `value`
   - 条件的值为空（如 `is` 的数组为空）时，这条条件不生效
   - 本周从周一开始
6. **排序**：空值不管升序还是降序都排在最后。前端的本地计算也这样做，两边不一致时，实时插入的新记录位置会和刷新后不同。
7. **冲突**：PATCH 带的 `version` 不是最新时返回 409 `VERSION_CONFLICT`，前端会重新拉视图和记录，并提示「内容已被别人修改，已为你刷新」。

### 3.3 记录列表

- 用已保存的视图时调 `GET /records?view_id=`，按 `page_token` 翻页，最多取 10000 条。
- `view_id` 返回 400 / 404 / 422（后端还不支持）时，前端退回到不带 `view_id` 取全部记录、本地计算。
- 没有保存权限的人改了筛选（临时筛选）时，前端不带 `view_id` 取全部记录，在本地计算。

### 3.4 分组

前端拿到记录后**在本地分组**，最多 3 级，组头显示本地统计的条数，没有用 `groups` 和 `group_path` 做组内分页。原因是记录已经全部取到前端（最多 1 万条），本地分组更简单，也能和实时刷新配合。后端返回的 `groups` 前端会解析，但暂时不用。如果以后单表会超过 1 万条，再改成按组分页。

折叠状态目前只记在内存里，切换数据表后会重置。

### 3.5 批量操作

- 用 `batch_create`、`batch_update`（两种写法都用到：统一改成同一个值，以及撤销时按每条记录的旧值回写）、`batch_delete { record_ids }`。
- 批量接口返回 404 / 405 时，前端改为逐条调用单条接口，结果按同样的 `succeeded / failed` 格式展示。
- `failed[].message` 请写中文，前端直接显示在失败明细里。
- 「删除视图里的全部」（`{ view_id, all: true }`）前端没用到：「选中全部 N 条」选的是前端已加载的记录，用 `record_ids` 发送。

### 3.6 实时事件

- 打开表时发 `{type: subscribe, topic: "table:<key>"}`，离开时发 unsubscribe；同一张表开了多个页面时按引用计数，最后一个离开才发 unsubscribe。WS 重连成功后，自动把所有订阅重新发一遍。
- `record.changed`：`created` 时插入并闪一下；`updated` 只替换这一条；`deleted` 时淡出。事件里没有 `record` 时（比如保密记录），前端重新拉整张表。前端用 `operator_id` 判断是不是自己改的，所以**请一定带上**。
- `table.schema_changed` 的 `version` 比本地新时，前端调 `GET /tables/:key`。
- `table.view_changed`：前端重新拉视图列表；当前视图的 `version` 变大而且配置变了时，提示「视图已被其他成员修改，已刷新」。
- `table.created` / `table.deleted`：刷新侧边栏；当前打开的表被删时提示。
- 前端额外处理了两个文档里没有的事件，后端可以选择推送：
  - `notification.read`：其他设备标了已读，前端重新拉未读数
  - `capabilities.changed`：后端开关变了，前端重新拉 `/capabilities`

### 3.7 通知

- 未读数取 `GET /notifications/unread-count`，返回 `{ "count": 3 }`（文档没写字段名）。
- `notification.new` 事件里带完整的 `notification` 对象，前端未读数加 1，打开着的面板会把它插到最前面。
- 点击通知会跳转到 `target` 指向的位置：
  - `record`：读 `target.table_key` 和 `target.id`，打开这张表并弹出这条记录。**请在 target 里带上 `table_key`。**
  - `doc` / `wiki`：跳到云文档；`task`：跳到任务；`calendar`：跳到日历；`chat`：打开会话。这几种目前只跳到对应模块，还不会定位到具体的评论、任务或日程（见第 4 节）。

### 3.8 推送设备

- 后端 `POST /devices` 现在只接受 `platform: ios | android`。需求文档写的是 macOS 也走 APNs，如果要支持 macOS 推送，请加上 `macos`。
- 前端还没接入 APNs / FCM SDK（需要苹果开发者推送证书和 Firebase 配置）。代码里预留了 `pushTokenProvider`（`app_state.dart`）：接入 SDK、拿到 token 后在 `main()` 里赋值即可。之后每次登录注册一次，token 变化时调 `onPushTokenChanged()` 重新注册，退出登录时先 `DELETE /devices/:id` 再注销令牌。
- 在这之前，通知设置页顶部会提示“这台设备还没有开启系统推送”。
