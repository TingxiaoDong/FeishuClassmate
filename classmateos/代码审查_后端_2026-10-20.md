## B1 机器人可往任意会话发消息【严重】

**位置**
- `server/routes-im.ts:577` `POST /api/v1/bot/messages`：`receive_id_type` 不是 `user_id` 时直接 `repo.getChat(receive_id)` 然后发消息，不检查机器人是不是这个会话的成员。
- `server/routes-realtime.ts:189` 大脑 WebSocket：除 `user_only` 事件外，所有会话的 `message.receive` 都推给大脑，包括两个同学之间的私聊。

**现象（已实测）**：u1 给 u2 私聊发「晚上一起吃饭？」，大脑收到事件、调了大模型，机器人成功往这个私聊里回了一条消息。

**影响**：同学私聊内容被转给大模型；机器人可在不相关的群里发言。

**修改建议**
1. `POST /bot/messages`：按 chat_id 发送时，要求 `chat.member_ids` 包含 `BOT_ID`，否则返回 403。
2. 大脑 WS：`message.receive` 只推送机器人是成员的会话（按 `member_ids` 过滤）。这是服务端兜底，agent 侧还要再按「单聊 / 群里 @」过滤（见 agent 文档 A1）。
3. 同样检查其他带 bot 令牌的写接口（卡片、编辑消息等）是否都限定在机器人所在会话。

**验收**：补测试：u1→u2 私聊消息不出现在大脑 WS；机器人往非成员会话发消息返回 403。

## B2 默认密钥和默认账号没有生产保护【严重】

**位置**：`server/main.ts:27-34`、`:79`

```ts
const secret = process.env.CLASSMATE_OS_SECRET ?? 'dev-only-secret-change-me';
const botToken = process.env.CLASSMATE_OS_BOT_TOKEN ?? 'dev-bot-token';
// 种子账号 admin / admin
.listen({ port, host: '0.0.0.0' })
```

**影响**：bot 令牌加上 `X-On-Behalf-Of` 请求头可以以任意同学（含管理员）身份读写数据。部署时漏配一个环境变量，整套系统就对外开放；签名密钥是公开的默认值，任何人都能伪造登录令牌。

**修改建议**
1. 非开发环境（如 `NODE_ENV=production`，或没有显式设置 `CLASSMATE_OS_DEV=1`）下，缺少 `CLASSMATE_OS_SECRET` / `CLASSMATE_OS_BOT_TOKEN`，或者值等于默认值时，直接拒绝启动。
2. 生产环境不创建 `admin/admin` 种子账号，或者首次登录强制改密（已有 `must_change_password` 机制，可以直接复用）。
3. bot 令牌比对改用 `crypto.timingSafeEqual`（先比长度）。
4. 监听地址改为可配置，开发环境默认 `127.0.0.1`。

**验收**：生产模式下不配环境变量启动会报错退出；用默认值启动同样会报错。

## B3 删除确认卡片不绑定具体操作，可重复使用【严重】

**位置**：`server/agent-principal.ts:185` `isValidConfirmCard`

现在只检查：卡片是机器人发的确认卡、没过期、指定同学点了「确认」、点确认在 10 分钟内。**不检查确认的是哪个操作、哪个对象，用过一次也不会作废。**

**影响**：同学确认删除 A 之后 10 分钟内，同一张卡片 id 可以放行任意多次、针对任意对象的删除。agent 一旦被文档或消息里的恶意内容诱导（提示词注入），这道护栏就挡不住。

**修改建议**（需与 agent 配合，agent 侧见 A2）
1. 卡片内容新增 `bound_action: { method, route, target_id }`（由 agent 发卡时写入，服务端在 `POST /bot/messages` 里校验确认卡必须带这个字段）。
2. `isValidConfirmCard` 增加参数：当前请求的 method、路由模板、目标 id，必须和 `bound_action` 一致。
3. 放行后在卡片上标记 `consumed_at`（用条件更新保证只成功一次），再次使用返回 409 `CARD_CONSUMED`。
4. 批量删除场景：`target_id` 支持数组，按集合比对。

**验收**：补测试：同一卡片第二次使用被拒；卡片绑的是删除 A，拿去删除 B 被拒；绑 DELETE 的卡片拿去调其他写接口被拒。

## B4 两个测试失败【较大】

全量 `vitest`：404 通过 / 2 失败 / 9 跳过。

### B4-1 agent 工具目录过期
- 失败用例：`tests/runtime/cos-tools.test.ts` 「接口目录与服务端路由一致」。
- 原因：今天新增了接口，没有重新生成 `catalog.generated.ts`，agent 调不到新接口。
- 修复：运行 `node scripts/gen-cos-catalog.mjs`，并把生成的文件一起提交。之后改接口时把这一步加进提交前检查（或 CI）。
- 生成后通知 agent 开发：检查新增的写入 / 删除类工具有没有配风险策略（见 agent 文档 A3）。

### B4-2 普通成员删不了自己建的表
- 失败用例：`tests/classmateos/phase2-iter1.test.ts` 「GET /tables 带 builtin / version / permissions…」。
- 原因：`server/table-access.ts:51` 现在删表要求 `can_manage` 加权限点 `table.delete`，测试预期创建者可以删。
- 需要先确定产品规则：
  - 创建者可以删 → 改 `table-access.ts`，让创建者不需要 `table.delete`；
  - 只有拥有 `table.delete` 的人能删 → 改测试，同时确认前端在 `can_delete=false` 时隐藏删除按钮。
