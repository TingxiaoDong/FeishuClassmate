> 版本：v1.0（2026-10-19）
> 适用前端：`classmateos/app`（Flutter，macOS / Windows / Web / Android / iOS 共用一份代码）
> 对照后端：`classmateos/server`（Fastify，内存 / PostgreSQL 两种存储）
> 读者：前端开发（主），后端开发（按第 3 节的接口约定并行实现）

## 0. 怎么读这份文档

每个功能都按同样的四块写：

| 小节 | 内容 |
|---|---|
| **页面与交互** | 前端要做什么，用户怎么用，对标飞书的哪个功能 |
| **接口** | 前端调用的接口和数据结构。标【已有】的可以直接用；标【新增】【需修改】的是**前后端约定的契约**，后端按这里实现，前端按这里写 mock |
| **权限与边界** | 谁能看、谁能改，空状态、出错时怎么显示 |
| **验收** | 做到什么程度算完成 |

编号规则：需求编号 `R-模块-序号`，如 `R-BT-03` 是多维表格第 3 条，验收清单（第 19 节）按编号逐条勾。

## 2. 通用约定（在一期基础上新增的部分）

一期《前端接口需求文档》第 2 节的约定全部沿用（基础地址、错误格式、时间格式、ID 不透明、`page_token` 分页）。新增以下几条：

### 2.1 功能开关：`GET /api/v1/capabilities`【新增】

二期功能会分批上线。前端**不要靠版本号判断**，统一读功能开关决定显示还是隐藏入口：

```json
{
  "features": {
    "table.create": true,
    "table.fields": true,
    "table.views": false,
    "doc.permissions": false,
    "doc.comments": false,
    "doc.versions": false,
    "wiki": false,
    "approval": false,
    "search": false,
    "message.thread": false,
    "message.reaction": false,
    "message.forward": false,
    "message.urgent": false,
    "calendar.recurrence": false,
    "task.subtasks": false,
    "notifications": false,
    "admin": false,
    "sheet": false,
    "auth.qr_login": false
  }
}
```

- 登录成功后拉一次，存在 `AppState` 里；WS 重连成功后再拉一次
- 不认识的 key 忽略；缺失的 key 当作 `false`
- 开关为 `false` 时：入口**隐藏**（不是置灰）；已经在页面里的按钮，点击后提示「这个功能还没开放」
- 接口本身返回 404（后端还没加这个接口）时，前端只开放一期已有功能 + `table.create`（按现有逻辑提示「后端尚未开放」）

### 2.2 权限字段统一写法

凡是要控制按钮显隐的对象，后端都返回 `permissions`，前端**只看它**，不要自己按创建者、管理员去推算：

```json
"permissions": { "can_view": true, "can_edit": true, "can_comment": true, "can_manage": false, "can_delete": false }
```

一期文档返回的 `can_edit` 保留兼容，二期新代码读 `permissions`。

### 2.3 新增错误码

| code | 状态码 | 场景 | 前端显示 |
|---|---|---|---|
| `FORBIDDEN` | 403 | 没有权限 | 后端 `message` |
| `FEATURE_DISABLED` | 404 | 功能没开放 | 「这个功能还没开放」 |
| `TABLE_NAME_EXISTS` | 409 | 表名重复 | 后端 `message` |
| `FIELD_IN_USE` | 409 | 删除被视图 / 关联引用的字段 | 后端 `message`，附带引用位置 |
| `VERSION_CONFLICT` | 409 | 并发修改（字段、视图、审批流程） | 「内容已被别人修改，已为你刷新」，然后重新拉取 |
| `APPROVAL_STATE_INVALID` | 409 | 审批单状态不允许这个操作（如已撤回） | 后端 `message` |
| `RATE_LIMITED` | 429 | 加急、导出等频繁操作 | 「操作太频繁，请稍后再试」 |

### 2.4 富文本里的「提及」统一结构

评论、话题回复、审批意见、任务评论里都可能 @ 人、引用文档。统一用一期消息的结构：

```json
{ "text": "请 @张三 看一下", "mentions": [{ "user_id": "ou_xxx", "name": "张三", "offset": 2, "length": 3 }] }
```

### 2.5 列表排序和过滤

新接口的列表统一支持 `page_size`（默认 50，最大 200）、`page_token`；需要排序的接口写 `sort=字段` 或 `sort=-字段`（倒序）。

## 4. 多维表格

前端现状：`bitable_page.dart`（表格视图 + 看板拖拽）、`bitable_field.dart`（字段渲染和编辑，支持类型 1/2/3/4/5/7/11/15/17）、`create_table_dialog.dart`（新建表）。筛选、排序、分组现在只在前端本地生效，刷新就丢。

### R-BT-01 新建数据表联调【P0】

**页面与交互**：前端已完成，见《多维表格新建数据表接口需求.md》。本期只做：
- 后端上线后去掉「后端尚未开放」的兜底提示，改为读 `capabilities.table.create`
- 创建成功后侧边栏把新表插在「自定义表」分组里并自动选中（内置表一组、自定义表一组，组标题可折叠）

**接口**：`POST /api/v1/tables`【新增】，契约以《多维表格新建数据表接口需求.md》为准。`GET /tables` 每张表新增 `builtin: true|false`、`permissions`。

**验收**：那份文档第 5 节 8 条全部通过；侧边栏分组正确。

### R-BT-02 字段管理【P0】

**页面与交互**（对标飞书多维表格的列头菜单）：
- 列头右侧下拉菜单：编辑字段、在左侧 / 右侧插入字段、按此字段升序 / 降序、按此字段分组、隐藏字段、删除字段
- 表头最右侧「+」新增字段，弹出和新建表弹窗同样的字段编辑面板（复用 `create_table_dialog.dart` 里的字段行组件，抽成 `field_editor.dart`）
- 拖动列头调整字段顺序（顺序属于**视图**，见 R-BT-03；只有在「字段管理」面板里拖才改表的默认顺序）
- 改类型时弹确认框，提示「已有 N 条记录的数据会按新类型转换，无法转换的会被清空」，后端返回预估影响条数
- 单选 / 多选的选项：可增删、改名、拖动排序、选颜色（`blue` `green` `orange` `red` `purple` `cyan` `yellow` `gray` 8 种）
- 内置表（`builtin: true`）的内置字段不可删、不可改类型，只能改显示名和选项；可以新增自定义字段

**接口**：

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/tables/:table_key/fields` | 新增字段，body 同新建表的 `fields[]` 一项，外加可选 `after_field`（插在谁后面） |
| PATCH | `/tables/:table_key/fields/:field_name` | 改 `title`、`type`、`required`、`options`、`option_colors`、`description`；`field_name` 不可改 |
| DELETE | `/tables/:table_key/fields/:field_name` | 删除字段；主字段不可删（422） |
| PUT | `/tables/:table_key/fields/order` | `{ "field_names": [...] }` 改默认顺序 |
| POST | `/tables/:table_key/fields/:field_name/convert-preview` | `{ "type": 2 }` → `{ "affected": 12, "will_clear": 3 }` 改类型前预估 |

选项改名要求后端**同步改已有记录里的值**；删除选项时，记录里的该值被清掉。所有字段接口返回整张表的最新定义（同 `GET /tables` 里的单个表对象），前端直接替换本地缓存。并发修改时带 `base_version`，冲突返回 409 `VERSION_CONFLICT`。

**权限与边界**：需要表的 `can_manage`。字段上限 100 个。

**验收**：新增 / 改名 / 改类型 / 删除 / 排序都能持久化，刷新后保持；别的用户实时看到（R-BT-05）；内置字段的删除按钮不出现。

### R-BT-03 视图（保存筛选、排序、分组、隐藏列）【P0】

**页面与交互**：
- 表名下方一排视图标签（对标飞书）：「表格视图」「看板」…，最后是「+ 新建视图」
- 每个视图独立保存：类型、筛选条件、排序、分组、隐藏字段、列宽、字段顺序、行高（紧凑 / 标准 / 宽松）、看板按哪个单选字段分列
- 工具栏「筛选」「排序」「分组」「隐藏字段」修改后**自动保存到当前视图**，所有人看到同样效果（和飞书一致）；视图右键：重命名、复制、删除、设为个人视图
- 个人视图只有自己能看到，图标加一个小人标记
- 看板拖拽改状态的现有逻辑保留，看板分列字段从视图里读，不再写死

**接口**：

```json
// View 对象
{
  "view_id": "vew_xxx",
  "name": "进行中的项目",
  "type": "grid",               // grid | kanban | calendar | gantt | gallery（后三种见 R-BT-11）
  "personal": false,
  "owner_id": null,
  "config": {
    "filter": { "conjunction": "and", "conditions": [{ "field_name": "status", "operator": "is", "value": ["进行中"] }] },
    "sort": [{ "field_name": "due", "desc": false }],
    "group": [{ "field_name": "owner", "desc": false }],
    "hidden_fields": ["notes"],
    "field_order": ["name", "status", "owner"],
    "field_widths": { "name": 240 },
    "row_height": "standard",
    "kanban_field": "status",
    "calendar": { "start_field": "start", "end_field": "end" }
  },
  "version": 3,
  "updated_at": "2026-10-19T11:22:00.000Z"
}
```

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/tables/:table_key/views` | 列出（公共视图 + 自己的个人视图），按 `order` |
| POST | `/tables/:table_key/views` | 新建 |
| PATCH | `/tables/:table_key/views/:view_id` | 改名、改 `config`（整体替换），带 `version` |
| DELETE | `/tables/:table_key/views/:view_id` | 最后一个视图不可删（422） |
| PUT | `/tables/:table_key/views/order` | 调整标签顺序 |
| GET | `/tables/:table_key/records?view_id=` | 【需修改】带 `view_id` 时由**后端**按视图的筛选、排序计算并分页 |

筛选运算符：`is` `is_not` `contains` `not_contains` `is_empty` `is_not_empty` `gt` `gte` `lt` `lte`，日期另外支持 `today` `this_week` `last_7_days` `this_month`。现有 `filter` 查询参数保留。

**权限与边界**：公共视图需要 `can_edit` 才能改配置；没有权限的人改筛选只在本地临时生效，工具栏显示「仅自己可见的临时筛选，<保存为个人视图>」。

**验收**：配好的视图刷新、换设备后保持；超过 500 条记录的表按视图筛选结果正确（后端计算）；两个人同时改同一视图时后改的人收到「已刷新」提示。

### R-BT-04 分组展示【P1】

**页面与交互**：表格视图按 1–3 个字段分组，组头显示值 + 条数，可折叠；组内可直接「+ 新增记录」，新记录自动带上分组字段的值。看板就是按单选字段的一级分组，复用同一套逻辑。

**接口**：`GET /records?view_id=` 返回里新增 `groups`（只在有分组时返回），前端按组渲染、组内分页：

```json
"groups": [{ "path": ["进行中"], "count": 12 }, { "path": ["已完成"], "count": 30 }]
```

组内加载：`GET /records?view_id=&group_path=["进行中"]`（JSON 编码后放 query）。

**验收**：500 条以上的数据分组计数准确；折叠状态记在本地。

### R-BT-05 数据实时刷新【P0】

**页面与交互**：别人新增、修改、删除记录，或改了字段、视图，当前打开的表**不刷新整页**就能看到：
- 新增：按当前视图排序插入，行首闪一下浅色背景 1 秒
- 修改：只更新对应单元格；如果自己正在编辑同一个单元格，不覆盖，编辑结束后提示「这条记录刚被 张三 修改过」
- 删除：行淡出；如果正打开这条记录的详情，详情页显示「记录已被删除」
- 字段 / 视图变化：重新拉表定义和当前视图

**接口**：用户 WS 新增事件（只推给有权看到这张表的人，保密记录只推给能看的人）：

```json
{ "event_type": "record.changed", "table_key": "projects", "action": "created|updated|deleted",
  "record_id": "rec_xxx", "record": { /* 新的完整记录，deleted 时省略 */ }, "changed_fields": ["status"], "operator_id": "ou_xxx" }
{ "event_type": "table.schema_changed", "table_key": "projects", "version": 8 }
{ "event_type": "table.view_changed", "table_key": "projects", "view_id": "vew_xxx", "action": "created|updated|deleted" }
{ "event_type": "table.created|table.deleted", "table_key": "tbl_xxx" }
```

为了不让没打开表格的客户端收一堆事件，前端打开某张表时发订阅消息，离开时取消：

```json
{ "type": "subscribe", "topic": "table:projects" }
{ "type": "unsubscribe", "topic": "table:projects" }
```

`table.created` / `table.deleted` 不需要订阅。断线重连后用现有的 `since` 续传；收到 `resync.required` 时重新拉当前视图第一页。

**验收**：两台设备同时打开同一张表，一边改另一边 1 秒内看到；机器人（飞书同学）写入的记录也能实时看到。

### R-BT-06 批量操作【P1】

**页面与交互**：行首复选框 + 表头全选（只选当前已加载的，另有「选中全部 N 条」链接）；选中后顶部出现操作条：批量修改某个字段、批量删除、复制为新记录、导出选中。Shift 连选，桌面端支持在单元格区域内 ⌘C / ⌘V 粘贴多行多列（从 Excel 复制过来也行）。

**接口**：

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/tables/:table_key/records/batch_create` | `{ "records": [{ "fields": {} }] }`，最多 500 条 |
| POST | `/tables/:table_key/records/batch_update` | `{ "records": [{ "record_id": "", "fields": {} }] }` 或 `{ "record_ids": [], "fields": {} }`（统一改成同一个值） |
| POST | `/tables/:table_key/records/batch_delete` | `{ "record_ids": [] }`，或 `{ "view_id": "", "all": true }` 删除视图里的全部 |

返回 `{ "succeeded": [...], "failed": [{ "record_id": "", "message": "" }] }`，部分失败时前端弹出失败明细。

**验收**：批量改 200 条、删 200 条成功；部分失败能看到原因；撤销（⌘Z）至少支持最近一次批量修改（前端用返回的旧值做反向 batch_update）。

### R-BT-07 导入、导出【P1】

**页面与交互**：
- 导入：表菜单「导入数据」→ 选 .xlsx / .csv → 预览前 20 行 → 列对应字段（自动按显示名匹配，可手动改、可「新建字段」）→ 选「追加」或「按主字段更新已有记录」→ 进度条 → 完成后显示成功 / 失败条数和失败原因下载
- 新建表弹窗增加「从 Excel 导入」入口，直接按表头生成字段
- 导出：视图菜单「导出为 Excel / CSV」，按当前视图的筛选、排序、隐藏列导出

**接口**：导入、导出都是异步任务：

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/tables/:table_key/imports` | `{ "file_key": "", "mode": "append|upsert", "mapping": { "列名": "field_name" } }` → `{ "job_id": "" }` |
| POST | `/tables/imports/preview` | `{ "file_key": "" }` → 表头、前 20 行、推荐字段类型 |
| POST | `/tables/:table_key/exports` | `{ "view_id": "", "format": "xlsx|csv", "record_ids": [] }` → `{ "job_id": "" }` |
| GET | `/jobs/:job_id` | `{ "status": "pending|running|done|failed", "progress": 0.6, "result": { "file_key": "", "succeeded": 0, "failed": 0, "error_file_key": "" } }` |

WS 也推 `job.updated`（字段同上），前端优先用事件，轮询作兜底（每 2 秒）。

**验收**：导入 5000 行的 xlsx 不卡界面；人员列按姓名自动匹配用户，匹配不到的进失败明细。

### R-BT-09 表的权限【P1】

## 5. 云文档

前端现状：`docs_page.dart`，Markdown 左右分屏编辑、自动保存，Yjs 协同（正文是 `Y.Text`，key `markdown`）；只有创建者能编辑，其他人只读。

### R-DC-01 分享与协作者权限【P0】

**页面与交互**（对标飞书文档右上角「分享」）：
- 文档顶栏右侧「分享」按钮 → 面板：
  - 添加协作者：搜索成员 / 部门 / 群，选角色「可阅读」「可编辑」「可管理」
  - 链接分享：关闭 / 组织内获得链接的人可阅读 / 可编辑；「复制链接」
  - 协作者列表：改角色、移除；「转移所有者」（仅所有者）
- 没有编辑权限的人：编辑器只读，顶栏显示「只能阅读」+「申请编辑权限」按钮，申请会给所有者发通知（第 12 节），所有者在通知里一键同意
- 文档列表（R-DC-05）显示每篇文档的所有者和自己的角色

**接口**：

```json
// GET /docs/:doc_id/permissions
{
  "owner_id": "ou_admin",
  "link_share": "off",                 // off | org_view | org_edit
  "members": [
    { "member_type": "user", "member_id": "ou_demo", "role": "editor" },
    { "member_type": "department", "member_id": "dept_robot", "role": "viewer" },
    { "member_type": "chat", "member_id": "chat_xxx", "role": "viewer" }
  ]
}
```

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/docs/:doc_id/permissions` | 查看（需 `can_view`） |
| PUT | `/docs/:doc_id/permissions` | 整体保存 `link_share` + `members`（需 `can_manage`） |
| POST | `/docs/:doc_id/transfer` | `{ "owner_id": "" }` 转移所有者 |
| POST | `/docs/:doc_id/access-requests` | 申请权限 `{ "role": "editor", "note": "" }` |
| POST | `/docs/:doc_id/access-requests/:request_id/approve` / `reject` | 所有者处理 |

角色：`viewer` `commenter` `editor` `manager`；所有者固定是 `manager` 且不可移除。`Doc` 对象返回 `permissions`（见 2.2）和 `my_role`。

**协同编辑的变化**：后端按角色决定协同连接是否可写（一期是只有创建者可写）。连接中被降权时，后端用新关闭码 **4410** 断开（4403 已用于「账号被禁用」，不要复用），前端重连后按新角色进入只读并提示「你的权限已变更」；权限被全部收回时重连会失败，前端显示「没有权限访问，申请权限」。

**验收**：给同事加「可编辑」后，同事能和自己同时编辑；改成「可阅读」后同事的编辑器立刻变只读；链接分享关闭时，非协作者打开显示「没有权限访问，申请权限」。

### R-DC-02 评论【P1】

**页面与交互**：
- 选中一段文字 → 浮动工具条「评论」→ 右侧评论栏出现输入框；被评论的文字加浅黄色底
- 文末「全文评论」区
- 评论支持 @ 人、回复（一层楼中楼）、表情回应、「解决」（解决后折叠，可在「已解决」里查看、重新打开）
- 手机端：评论栏改成底部抽屉，正文里评论位置显示气泡图标

**接口**：

```json
// Comment
{ "comment_id": "", "doc_id": "", "quote": "被选中的原文", "anchor": { "yjs_relative_start": "base64", "yjs_relative_end": "base64" },
  "is_whole": false, "solved": false, "replies": [{ "reply_id": "", "user_id": "", "content": { "text": "", "mentions": [] }, "created_at": "" }],
  "created_by": "", "created_at": "" }
```

锚点用 Yjs 的 `RelativePosition`（编码后 base64），正文被改动时位置能跟着走；原文被删光时显示「原文已删除」。

| 方法 | 路径 |
|---|---|
| GET | `/docs/:doc_id/comments?solved=false` |
| POST | `/docs/:doc_id/comments`（新评论，带第一条回复） |
| POST | `/docs/:doc_id/comments/:comment_id/replies` |
| PATCH / DELETE | `/docs/:doc_id/comments/:comment_id/replies/:reply_id`（只能改删自己的） |
| PATCH | `/docs/:doc_id/comments/:comment_id` `{ "solved": true }` |

WS 事件 `doc.comment_changed { doc_id, comment_id, action }`（打开文档时订阅 `doc:<doc_id>`）。需要 `can_comment`（`commenter` 及以上）。

### R-DC-03 历史版本【P1】

**页面与交互**：顶栏「…」→「历史记录」→ 右侧列表按时间倒序（谁、什么时候、改了多少字）；点某一版：正文区显示那一版，和当前版本对比时新增标绿、删除标红划线；「还原此版本」（需 `can_edit`，还原本身也生成一个新版本）；可以给某个版本命名（如「组会前定稿」）。

**接口**：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/docs/:doc_id/versions` | `[{ "version_id", "name", "created_by", "created_at", "added": 120, "removed": 30 }]` |
| GET | `/docs/:doc_id/versions/:version_id` | 返回该版本 `markdown` |
| PATCH | `/docs/:doc_id/versions/:version_id` | `{ "name": "" }` |
| POST | `/docs/:doc_id/versions/:version_id/restore` | 还原；后端会以 4409 断开协同连接（一期已有行为），前端重连 |

后端在「停止编辑 2 分钟」或「距上个版本 30 分钟」时自动存一版。差异对比由前端算（按行 diff 即可）。

### R-DC-04 插入图片和附件【P0】

**页面与交互**：
- 工具栏「插入图片」「插入附件」；直接粘贴截图、拖拽文件进编辑区都会自动上传
- 上传中在光标处显示占位 `![上传中…]()`，完成后替换成正式地址；失败显示「上传失败，点击重试」
- 预览区图片点击放大；附件显示成卡片（图标 + 文件名 + 大小），点击下载
- 图片最大 20 MB，附件沿用云盘上限

**接口**：复用一期 `POST /files/upload-url` + `PUT` 直传，新增参数 `ref: { "type": "doc", "id": "doc_xxx" }`，让文件和文档绑定（文档能看的人就能看图）。Markdown 里写 `![描述](cos-file://file_key)`，**不写签名地址**（签名会过期）；渲染时前端把 `cos-file://` 换成 `GET /files/:file_key/download-url` 拿到的地址，带本地缓存。

**验收**：粘贴截图 3 秒内显示；文档分享给同事后同事能看到图片；文档删除后图片随之清理（后端引用计数，一期已有机制）。

### R-DC-05 文件夹与文档空间【P1】

**页面与交互**：云文档左栏改成：「主页（最近访问）」「我的空间」「共享给我」「收藏」「知识库（跳到 Wiki 模块）」「回收站」。我的空间里可以建多层文件夹，拖拽移动。删除进回收站，30 天内可恢复。

**接口**：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/docs?scope=recent\|mine\|shared\|starred\|trash&folder_id=` | 【需修改】`scope` 增加取值，`folder_id` 列文件夹内容 |
| POST / PATCH / DELETE | `/folders`、`/folders/:folder_id` | 新建、改名、移动（`parent_id`）、删除 |
| PATCH | `/docs/:doc_id` | 【需修改】增加 `folder_id` |
| POST / DELETE | `/docs/:doc_id/star` | 收藏 / 取消 |
| POST | `/docs/:doc_id/restore` | 从回收站恢复 |
| DELETE | `/docs/:doc_id?permanent=true` | 彻底删除 |

`GET /docs` 列表项新增 `folder_id`、`owner_id`、`my_role`、`starred`、`last_viewed_at`、`deleted_at`。打开文档时后端记「最近访问」，前端不用单独调。

### R-DC-06 导出【P1】

顶栏「…」→「下载为」：Markdown（前端直接生成）、PDF、Word（.docx）。PDF / Word 走异步任务：`POST /docs/:doc_id/exports { "format": "pdf|docx" }` → `job_id`，同 R-BT-07 的 `/jobs/:job_id`，完成后自动下载。图片要一起导出。

### R-DC-07 模板中心【P2】

新建文档时可选「空白文档」或模板。内置模板：组会纪要、周报、实验记录、论文阅读笔记、项目立项、访客讲解稿。管理员可把任意文档「设为模板」。接口：`GET /doc-templates`、`POST /doc-templates { "doc_id": "" }`、`POST /docs { "template_id": "" }`。

### R-DC-08 文档内嵌内容【P2】

Markdown 扩展块语法，预览区渲染为可交互组件：

````
```cos-embed
{ "type": "bitable_view", "table_key": "projects", "view_id": "vew_xxx" }
```
````

`type` 支持 `bitable_view`（只读表格，点击跳转）、`task_list`（任务清单，能勾选完成）、`doc_link`（文档卡片）。工具栏「插入」菜单生成这段代码，不需要用户手写。

### R-DC-09 协同光标【P1】

多人同时编辑时，编辑区显示其他人的光标和选区（颜色 + 名字小标签），顶栏显示正在看这篇文档的人的头像（最多 5 个，多了显示 +N）。用 Yjs awareness 协议实现：后端协同服务**已经会原样转发** awareness 消息（消息类型 1，见 `server/collab.ts`），这一条**纯前端就能做**。前端在 awareness 里放 `{ user_id, name, color, cursor }`，`cursor` 用 Yjs `RelativePosition`；只读用户也广播 awareness（只显示头像，不显示光标）。

首批上线 3 个审批模板：**设备借用**（对接 `Equipment` / `Reservations` 表）、**报销**、**请假**。

### R-AP-01 发起审批【P0】

**页面与交互**：
- 审批首页上方「发起申请」：模板卡片网格（图标 + 名称 + 说明）
- 点模板 → 表单页，控件由模板定义动态渲染；底部显示**流程预览**（按当前填写内容算出的审批人链路，例如「导师 张老师 → 设备管理员 李四」），抄送人可自己加
- 提交前校验必填；可「存草稿」
- 设备借用表单的「设备」控件从 `Equipment` 表选（只列状态为「空闲」的），借用时间选完后实时检查和 `Reservations` 是否冲突

**表单控件类型**（模板 `form` 数组里的 `type`）：

| type | 控件 | 说明 |
|---|---|---|
| `input` | 单行文本 | |
| `textarea` | 多行文本 | |
| `number` / `amount` | 数字 / 金额 | 金额带币种，两位小数 |
| `date` / `date_range` | 日期 / 日期区间 | 区间自动算天数 |
| `radio` / `checkbox` | 单选 / 多选 | `options` |
| `user` / `department` | 选人 / 选部门 | |
| `attachment` / `image` | 附件 / 图片 | 复用文件上传 |
| `bitable_record` | 选多维表格记录 | `property: { "table_key": "equipment", "filter": {...} }` |
| `detail` | 明细（可加多行的子表单） | 报销用，`children` 是子控件，可设合计字段 |
| `description` | 说明文字 | 只读 |

**接口**：

```json
// Template（GET /approval/templates）
{ "template_id": "apt_equipment", "name": "设备借用", "icon": "devices", "description": "",
  "form": [{ "id": "equipment", "type": "bitable_record", "label": "借用设备", "required": true,
             "property": { "table_key": "equipment", "filter": { "conditions": [{ "field_name": "status", "operator": "is", "value": ["空闲"] }] } } },
           { "id": "period", "type": "date_range", "label": "借用时间", "required": true }],
  "version": 4 }
```

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/approval/templates` | 我能发起的模板 |
| GET | `/approval/templates/:template_id` | 详情（含 `form`） |
| POST | `/approval/preview-flow` | `{ "template_id", "form_values": {} }` → 审批节点列表（用于流程预览，表单变化时防抖 500ms 调） |
| POST | `/approval/instances` | `{ "template_id", "template_version", "form_values": {}, "cc_user_ids": [], "client_request_id" }` |
| POST / GET | `/approval/drafts`、`/approval/drafts/:draft_id` | 草稿 |

### R-AP-02 审批处理【P0】

**页面与交互**：审批单详情页：
- 顶部：标题（「张三的设备借用」）、状态标签（审批中 / 已通过 / 已拒绝 / 已撤回）、编号
- 中间：表单内容（只读）
- 右侧（手机在下方）：**流程时间线**——每个节点的审批人、结果、意见、时间；当前节点高亮
- 底部操作条按权限显示：
  - 当前审批人：同意（可填意见）、拒绝（意见必填）、转交、加签（前加签 / 后加签）、退回到某个节点
  - 发起人：撤回（还没人审批时）、催办（每小时一次，给当前审批人发加急）
  - 所有能看的人：评论（可 @）
- 审批人手机上收到「飞书同学」发来的审批卡片，卡片上能直接「同意」「拒绝」（拒绝跳详情填意见）

**接口**：

```json
// Instance
{ "instance_id": "api_xxx", "serial": "202610190001", "template_id": "", "title": "张三的设备借用",

  "nodes": [{ "node_id": "", "name": "导师审批", "type": "approve|cc", "mode": "and|or",
              "status": "done|current|waiting", "approvers": [{ "user_id", "result": "approved|rejected|transferred|pending", "comment", "at" }] }],
  "permissions": { "can_approve": true, "can_cancel": false, "can_urge": false, "can_comment": true },
  "created_at": "", "updated_at": "" }
```

|---|---|---|
| GET | `/approval/instances/:instance_id` | |
| POST | `/approval/instances/:instance_id/approve` | `{ "comment" }` |
| POST | `/approval/instances/:instance_id/reject` | `{ "comment" }`（必填） |
| POST | `/approval/instances/:instance_id/transfer` | `{ "user_id", "comment" }` |

| POST | `/approval/instances/:instance_id/cancel` | |
| POST | `/approval/instances/:instance_id/urge` | |
| GET / POST | `/approval/instances/:instance_id/comments` | |

### R-AP-03 审批中心【P0】

审批模块左栏 4 个列表：**待我审批**（带数量）、**我已审批**、**我发起的**、**抄送我**；每个列表支持按模板、状态、时间筛选和关键字搜索。列表项：标题、发起人头像、摘要（表单前 2 个字段）、状态、时间。待我审批支持多选「批量同意」。

**接口**：`GET /approval/instances?box=todo|done|mine|cc&template_id=&status=&q=&page_token=`；`POST /approval/instances/batch-approve { "instance_ids": [], "comment" }`。

### R-AP-04 审批模板管理【P1】

管理员在「管理后台 → 审批模板」（或审批模块右上角「管理」）里：
- **表单设计器**：左侧控件库拖到中间画布，右侧配置属性（名称、必填、选项、默认值）；手机端只读不可设计
- **流程设计器**：竖向节点图，节点类型「审批」「抄送」「条件分支」；审批人可选：指定成员、发起人的上级 / 部门负责人（依赖 R-AD-02 组织架构）、发起人自选、角色（依赖 R-AD-03）、表单里的人员字段（如「设备管理员」取自所选设备记录的负责人字段）；多人审批选「会签（都同意）」或「或签（一人同意）」；条件分支按表单字段（如「金额 > 1000」）
- 谁可以发起（所有人 / 部门 / 成员）、启用 / 停用；保存生成新版本，进行中的审批单按旧版本走完

**接口**：`POST /approval/templates`、`PUT /approval/templates/:template_id`（带 `version`）、`PATCH /approval/templates/:template_id { "enabled": false }`，模板对象多 `flow`（节点树）和 `initiators` 字段，具体结构前后端在迭代 3 开始前单独对一次。

### R-AP-05 审批联动多维表格【P1】

模板可配「审批通过后」动作：
- 设备借用：通过后在 `Reservations` 新增一条（设备、借用人、开始结束时间、关联审批单号），并把 `Equipment` 状态改为「借出」；归还时（借用人在审批单详情点「归还」）改回「空闲」
- 通用：「写入多维表格」动作，表单字段 → 表字段的映射

前端只需要：模板管理里配置动作的界面；审批单详情里显示「已写入：Reservations · 记录名」链接，点击跳到记录。接口字段 `instance.linked_records: [{ "table_key", "record_id", "title" }]`。

## 11. 全局搜索（新模块）

### R-SR-01 全局搜索【P1】

**页面与交互**（对标飞书顶部搜索）：
- ⌘K / Ctrl+K 打开搜索浮层；输入即搜（防抖 300ms）
- 默认「综合」：按类型分组，每组最多 3 条 + 「查看更多」：联系人、群、消息、云文档、知识库、多维表格记录、任务、日程、审批
- 顶部标签切换只看某一类；每类有专属筛选（消息：会话、发送人、时间；文档：所有者、更新时间；记录：表）
- 结果高亮关键字；回车打开第一条；方向键上下选
- 打开搜索浮层未输入时显示「最近搜索」和「最近访问」
- 消息结果点击跳到会话并定位到那条消息（一期已有定位能力）

**接口**：

```
GET /api/v1/search?q=标定&types=user,chat,message,doc,wiki,record,task,event,approval&page_size=3
```

```json
{
  "groups": [
    { "type": "doc", "total": 12, "items": [
      { "id": "doc_xxx", "title": "机械臂<em>标定</em>流程", "snippet": "…先做手眼<em>标定</em>…", "updated_at": "",
        "extra": { "owner_id": "ou_admin" } } ],
      "page_token": "..." }
  ]
}
```

- 单类型翻页：`GET /search?q=&types=doc&page_token=`
- 高亮只用 `<em>`，前端把它转成高亮样式，其他标签一律当文本
- 结果**必须按权限过滤**：看不到的文档、保密记录、不在的群的消息都不能出现
- 最近搜索存在前端本地（最多 20 条），不需要接口；最近访问用 `GET /recent`（文档、知识库页面、表、记录、审批单统一的最近访问，后端打开详情时自动记）
- 中文要分词（「标定流程」要能搜到「流程的标定」）

**验收**：1 万条消息 + 1000 篇文档下，搜索 500ms 内返回；看不到的内容一条都搜不出来。

### R-NT-02 手机推送与通知设置【P0】

**页面与交互**：

- iOS / macOS 用 APNs，Android 用 FCM；第一次启动时请求通知权限，用户拒绝时在「我的 → 通知设置」顶部提示去系统设置打开
- 点推送打开对应页面：推送 payload 带 `target`（同上），前端路由过去
- 「我的 → 通知设置」：总开关；分类开关（消息、@我、审批、任务、日程、评论）；免打扰时段（如 23:00–08:00）；「桌面端在线时手机不推送」开关；通知是否显示消息内容
- 桌面端：应用在后台时用系统通知（macOS 通知中心 / Windows 通知）

**接口**：【已有】`POST /devices`、`GET /devices`、`DELETE /devices/:device_id`；【新增】`GET/PUT /users/me/notification-settings`：


后端需要配好 APNs / FCM 证书，前端联调前确认。

## 13. 管理后台（新模块，仅管理员）

桌面端优先，手机端只做查看。导航上 `role != admin` 时不显示。后续 R-AD-03 上线后改为按权限点 `admin.*` 判断。

### R-AD-01 成员管理【P1】

成员列表（表格）：姓名、账号、部门、职位、角色、状态（正常 / 已禁用）、最后登录时间；搜索和按部门、状态筛选。操作：添加成员、编辑资料、禁用 / 启用、重置密码（显示一次性新密码供复制）、强制下线、**批量导入**（下载模板 xlsx → 上传 → 预览 → 导入，走 R-BT-07 的 job 机制）。

### R-AD-03 角色与权限【P1】

角色列表：内置「超级管理员」「管理员」「成员」，可新建自定义角色（如「设备管理员」「导师」）。每个角色勾选权限点，并添加成员。

| 权限点 | 说明 |
|---|---|

| `admin.roles` | 管理角色 |
| `admin.audit` | 查看操作日志 |
| `admin.security` | 安全设置 |

### R-AD-04 操作日志【P1】

表格：时间、操作人、操作类型、对象、详情、IP、设备；按时间范围、操作人、类型筛选；导出 CSV。覆盖：登录 / 登出 / 登录失败、成员和权限变更、删除文档 / 表 / 记录、文件下载、分享权限变更、审批模板变更。

### R-AD-05 安全设置【P2】

- 密码规则（最短长度、必须含字母数字）、首次登录强制改密码
- 会话：access 令牌有效期、闲置多久自动退出

接口：`GET/PUT /admin/security-settings`；`GET /users/me/sessions`、`DELETE /users/me/sessions/:session_id`。

接口：`POST /auth/qr { "device_name" }` → `{ "qr_id", "qr_content", "expires_at" }`；桌面轮询 `GET /auth/qr/:qr_id`（或 WS）→ `waiting|scanned|confirmed(带令牌)|expired|canceled`；手机 `POST /auth/qr/:qr_id/scan`、`/confirm`、`/cancel`。

### R-LG-03 「我的」页【P1】

手机底部第 5 个标签 / 桌面头像菜单：个人资料（头像上传、签名、电话，一期 `PATCH /users/me` 已有）、通知设置（R-NT-02）、登录设备（R-AD-05）、收藏（R-IM-06）、修改密码（`POST /users/me/password { "old_password", "new_password" }`【新增】）、服务器设置、退出登录、「退出所有设备」。

## 17. 新增实时事件汇总

都走一期的用户 WS（`/api/v1/events/ws`），断点续传、心跳、关闭码不变。前端不认识的事件继续忽略。

| event_type | 推给谁 | 需要订阅 | 章节 |
|---|---|---|---|
| `record.changed` | 能看到这张表 / 这条记录的人 | `table:<key>` | R-BT-05 |
| `table.schema_changed` / `table.view_changed` | 能看到这张表的人 | `table:<key>` | R-BT-05 |
| `table.created` / `table.deleted` | 能看到这张表的人 | 否 | R-BT-05 |
| `job.updated` | 发起人 | 否 | R-BT-07 |
| `doc.comment_changed` | 能看文档的人 | `doc:<id>` | R-DC-02 |
| `doc.permission_changed` | 被影响的人 | 否 | R-DC-01 |
| `wiki.node_changed` | 能看空间的人 | `wiki:<space_id>` | R-WK-02 |
| `message.read`（改为推全员） | 会话成员 | 否 | R-IM-01 |
| `message.urgent` | 被加急的人 | 否 | R-IM-05 |
| `approval.updated` / `approval.todo_count` | 相关人 / 本人 | 否 | R-AP-02 |
| `notification.new` | 本人 | 否 | R-NT-01 |
| `capabilities.changed` | 所有人 | 否 | 2.1 |

客户端发送的新消息：`{ "type": "subscribe" | "unsubscribe", "topic": "..." }`；后端回 `{ "event_type": "subscribed", "topic": "..." }`，没有权限时回 `{ "event_type": "subscribe_failed", "topic", "code": "FORBIDDEN" }`。重连后前端要**重新订阅**当前打开的 topic。

## 18. 前后端并行开发方式

1. **先定契约**：每个迭代开始第一天，前后端对一遍本文对应章节，有改动直接改本文（改版本号和下方修订记录），然后再开工。
2. **前端用 mock 开发**：在 `api_client.dart` 外面加一层 `MockApi`（`--dart-define=COS_MOCK=wiki,approval` 打开对应模块的假数据），按本文的结构返回；后端上线一个模块就去掉一个模块的 mock。WS 事件也做一个本地假事件源，方便测实时刷新。
3. **功能开关兜底**：所有新入口读 `capabilities`（2.1），后端没上线的功能不会出现在正式包里。
4. **契约测试**：前端在 `app/test/api_contract_test.dart` 里为每个新接口加请求体断言（和新建数据表的做法一样）；后端在 `tests/classmateos/frontend-contract.test.ts` 补对应用例。
5. **机器人侧同步**：凡是影响「飞书同学」读写的（Wiki、视图、审批、任务清单），PAL 层 `src/pal/` 的 `ClassmateOSAdapter` 要同步补上，避免机器人和界面看到的数据不一致。
