# ClassmateOS 后端对接说明

对应《前端接口需求文档》。本次把后端按文档重写：P0、P1 全部完成，P2 完成了大部分（见文末「还没做的」）。

## 1. 怎么启动

```bash
# 内存模式（开发联调，重启后数据丢失）
pnpm classmateos

# PostgreSQL 模式（数据持久化，启动时自动建表，可重复执行）
DATABASE_URL=postgresql://user:pass@localhost:5432/classmateos pnpm classmateos
```

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `DATABASE_URL` | 不设 = 内存 | 设置后用 PostgreSQL；自动执行 `schema.sql`（23 张业务表）和 `schema-platform.sql`（账号 / IM / 文件 / 日历 / 任务 / 文档 / 设备） |
| `CLASSMATE_OS_PORT` | 8080 | |
| `CLASSMATE_OS_SECRET` | dev-only-secret-change-me | 令牌签名密钥，**生产必须改** |
| `CLASSMATE_OS_BOT_TOKEN` | dev-bot-token | 机器人网关令牌 |
| `CLASSMATE_OS_USERS` | admin/admin、demo/demo | 种子账号 JSON：`[{user_id,name,password,role,department?,title?,email?}]`。**只在库里没有这个账号时插入**，已有账号不会被覆盖（改密码用管理员接口） |
| `CLASSMATE_OS_FILE_DIR` | PG 模式 `./data/files`，内存模式系统临时目录 | 上传文件存放目录 |
| `CLASSMATE_OS_MAX_FILE_MB` | 200 | 单文件上限，超出返回 413 |
| `CLASSMATE_OS_QUOTA_GB` | 10 | `/files/usage` 返回的配额 |

## 3. 前端需要知道的行为

**通用**
- 错误一律 `{ "message": "中文说明", "code"?: "..." }`；参数错误 422 + `code: "VALIDATION_FAILED"` + `errors: [{field, message}]`
- 常用 code：`UNAUTHORIZED`、`ACCOUNT_DISABLED`、`REFRESH_EXPIRED`、`CHAT_NOT_FOUND`、`CHAT_NOT_MEMBER`、`CARD_ANSWERED`、`CARD_EXPIRED`、`FILE_TOO_LARGE`、`DOC_CONFLICT`、`CURSOR_NOT_FOUND`、`NOT_FOUND`
- 带 `content-type: application/json` 但没有请求体的请求（如 DELETE）不会再报 400
- 列表接口统一带 `total`；分页用 `page_token`（没有更多时不返回或为 null）
- 新增 `GET /api/v1/health`

**认证**
- access_token 2 小时，refresh_token 30 天；refresh 每用一次就轮换，旧的立即作废；`POST /auth/logout` 吊销
- refresh_token 当 Bearer 用一律 401
- 登录失败的 message 保持 `invalid credentials`
- 管理员接口：`POST /users`（加人）、`PATCH /users/:id`（改资料、禁用、重置密码）；普通成员 `PATCH /users/me` 只能改头像、签名、电话

**消息**
- 会话列表按最后活动时间倒序（置顶靠前请前端按 `pinned` 处理），带 `unread_count`、`last_message`、`last_read_message_id`、`pinned`、`muted`、`kind`
- `POST /chats {chat_type:"p2p"}` 对同一个人去重：已存在返回 200 + 原会话，新建返回 201
- `name="我的云盘"` 且没有其他成员的会话自动标成 `kind:"drive"`，发进去的自己的文件自动登记到云盘（过渡期约定保持可用）
- 群聊改名 / 改公告 / 加人 / 退群 / 移人都会插入 `msg_type:"system"` 消息
- 群主退群自动转给最早加入的成员
- 消息分页：默认和 `before_message_id` 倒序；`after_message_id` 正序；`page_size` 最大 500
- 发送者自己发的消息自动算已读
- `client_msg_id` 重复时返回 200 和原消息（不重复入库）
- 撤回：发送者 2 分钟内（管理员不限），撤回后 `recalled:true`、`content:{}`
- 卡片：回答后 `content.answer = {user_id, action, answered_at}`；机器人可调 `POST /bot/cards/:card_id/expire` 标记 `content.expired = true`

**实时事件**
- 用户 WS 只推当前用户有权看到的事件；`card.action` 只给 bot WS
- `since` 断点续传：找不到时先发 `{"event_type":"resync.required"}`
- 心跳：每 30 秒 WS ping 帧 + 文本帧 `{"event_type":"ping"}`；客户端发 `{"type":"ping"}` 回 `{"event_type":"pong"}`
- 关闭码：4401 令牌无效 / 过期（连接中令牌过期也会 4401），4403 账号被禁用
- 事件缓冲在进程内存（最近 2000 条），服务重启后旧 `since` 会收到 `resync.required`

**文件**
- 下载响应带真实 `Content-Type`、`Content-Disposition`（含 UTF-8 中文文件名）、支持 Range
- html / svg / xml / js 一律按附件下载，防 XSS
- 看不到的文件 `download-url` 返回 404
- `DELETE /files/:key`：会话或表格里还引用着就只移出云盘，没人引用了才真正删除

**多维表格**
- `GET /tables` 每个字段都有 `title`（中文）、`options`、`option_colors`、`required`；每张表有 `name`、`description`、`icon`、`primary_field`
- 记录列表带 `total`（已扣除保密记录）、`created_by`、`updated_by`；支持 `keyword`
- 筛选条件写了不存在的字段或格式不对返回 422（以前内存版会静默返回空）
- 人员字段的 id 必须是存在的用户，附件字段的 file_key 必须存在且自己能访问，否则 422；附件会补上 `file_name`、`size`、`content_type`

**云文档**
- `POST /docs` 直接返回完整 Doc（保留 `doc_id`、`url`），`markdown` 可省略
- Doc 带 `created_at`、`updated_by`、`can_edit`、`summary`（前 80 字）
- 列表按 `updated_at` 倒序，支持 `scope`、`keyword`、分页
- `PATCH` 带 `base_updated_at` 时做并发保护，冲突返回 409 + 最新 `doc`
- 文档内容按创建者可编辑处理；管理员可以删除但不能编辑

**协同编辑（回答文档 9.6 的三个问题）**
1. 正文共享类型：`Y.Text`，key = `"markdown"`
2. 非创建者连接是只读：能收到同步和别人的修改，发出的修改服务端丢弃
3. REST `PATCH markdown` 会清掉协同态，并以关闭码 4409 断开正在协同的连接（前端重连即可从新内容开始）；删除文档以 4404 断开

**日历 / 任务**
- 日程带 `created_at`、`updated_at`、`location`、`all_day`、`attendees[].rsvp`、`color`、`reminders`；创建者自动 `accepted`，其他人 `pending`
- `PATCH /calendar/events/:id` 仅创建者；`POST /calendar/events/:id/rsvp` 参与人回复
- `GET /calendar/events?user_id=` 查同事忙闲，只返回时间段
- 新建 / 新增参与人推送 `calendar.invited`；指派任务给别人推送 `task.assigned`
- 任务 `PATCH` 中 `null` 表示清空；可以改 `assignee_id`；变为 `done` 时写 `completed_at`，改回其他状态清空
- `DELETE /tasks/:id` 仅创建者（负责人 403）
- `GET /tasks` 支持 `assignee_id=me`、`created_by=me`

## 4. 和以前行为不同的地方

- 默认种子账号 id 仍是 `ou_admin` / `ou_demo`，登录名 `admin` / `demo` 不变
- 建会话时成员必须是存在的用户（以前随便填也能建）
- 用户 WS 除 `message.receive` 外还会收到 chat.* / message.updated / message.read 等事件，前端不认识的事件请忽略
- 机器人账号 `bot`（显示名「飞书同学」）会出现在成员列表里，方便前端翻译名字；它不能登录
- 旧测试已按新行为更新：`pg-store.test.ts`（SQL 带 total、数字按数值比较）、`user-ws.test.ts`、`bot-events.test.ts`、`bot-gateway.test.ts`（补测试账号）、`collab.test.ts`（非创建者只读）

```bash
# 全部测试（内存版）
./node_modules/.bin/vitest run

# 验收清单契约测试同时在真 PostgreSQL 上跑（会清空该库，请用专门的测试库）

  ./node_modules/.bin/vitest run tests/classmateos/frontend-contract.test.ts
```

## 6. 还没做的（文档里标 P2 的部分）

- 日程重复规则 `recurrence`；邀请 / 指派时由机器人发通知消息（现在只推送 WS 事件）
- 任务：负责人只能改状态和描述的细分权限、分页、子任务
- 多维表格：批量接口、视图、字段管理、`record.changed` 推送、按角色隐藏数据表
- 云文档：协作者权限、评论、历史版本
- `message.read` 推给会话其他成员（现在只推给本人其他设备）
- 报表 `?range=`、`GET /workbench/apps`
- 文件存储仍是本地磁盘（S3 / MinIO 接口已预留）；WS 事件缓冲在单进程内存，多实例部署需要换成 Redis 等共享队列
